# 既存リストとの差分管理

## 差分管理の基本

RPP除外CSVは「上書き」ではなく「追加・削除・更新」で管理。コントロールカラム n/d/u を正しく使う。

### 状況別の判定

| 既存リスト | 今回除外条件 | 操作 |
|---|---|---|
| なし | 該当 | n（新規追加） |
| あり | 該当 | （変更なし） |
| あり | 非該当 | d（除外解除＝削除） |
| あり | 該当（理由変更） | u（更新） |

## 既存リストの保管

### バックアップ方針

- 適用前の除外リストCSVを保管
- 月次で日付付きアーカイブ
- 例：`exclusion_2024-05-15.csv`、`exclusion_2024-06-01.csv`

### バージョン管理

- 大きな変更時は変更履歴を別ファイルに記録
- 「いつ・誰が・なぜ」を明示

## 差分処理のロジック

### 擬似コード

```
既存リスト = 前回の除外リスト
新規対象 = 今回の判定で除外すべき商品
削除対象 = 今回の判定で除外解除すべき商品（既存にあり、新規対象に無い）
新規追加 = 今回の新規対象（既存に無いもの）

出力CSV：
  for 商品 in 新規追加:
    n, 商品ID, 理由
  for 商品 in 削除対象:
    d, 商品ID, 解除理由
```

### Python例

```python
import csv

# 既存除外リスト読み込み
with open('existing_exclusion.csv', 'r', encoding='shift_jis') as f:
    existing = {row['item_id'] for row in csv.DictReader(f)}

# 今回除外候補
today_target = {'SKU-001', 'SKU-002', 'SKU-003', 'SKU-005'}

# 差分計算
to_add = today_target - existing
to_delete = existing - today_target

# 差分CSV出力
with open('rpp_exclusion_diff.csv', 'w', encoding='shift_jis', newline='') as f:
    writer = csv.writer(f, lineterminator='\r\n')
    writer.writerow(['control', 'item_id', 'reason'])
    
    for item in to_add:
        writer.writerow(['n', item, '在庫切れ'])
    
    for item in to_delete:
        writer.writerow(['d', item, '在庫補充済み'])
```

## 重複の検出と排除

### 重複チェック

```python
# CSV内重複
seen = set()
duplicates = []
for row in csv_data:
    if row['item_id'] in seen:
        duplicates.append(row['item_id'])
    seen.add(row['item_id'])

# 既存リストとの重複
already_excluded = today_target & existing
# → これらは「変更なし」、CSVに含めない
```

### 重複時の優先度

複数条件で該当する場合の理由欄：

```
複数該当時の優先順位：
1. 在庫切れ（最優先）
2. 粗利マイナス
3. 廃番予定
4. 季節終了
5. ROAS悪化
```

## 適用前のシミュレーション

### 影響範囲の試算

| 項目 | 計算 |
|---|---|
| 除外件数 | n件数 |
| 復活件数 | d件数 |
| 純除外増減 | n - d |
| 過去30日広告費 | 除外対象商品の過去30日広告費合計 |
| 過去30日売上 | 同上の売上合計 |
| 削減見込み | 過去30日広告費 |
| 失う売上 | 過去30日売上 |
| ネット粗利改善 | （失う粗利）-（削減広告費） |

→ ネット粗利改善がプラスなら除外する価値あり。

## 適用後の確認

### 24時間後にチェック

- 除外したはずの商品に広告流入していないか
- RPP管理画面の除外リスト件数
- ROASが改善しているか

### 1週間後にチェック

- 除外による広告費削減効果
- 売上への影響
- 除外解除すべき商品はないか

## ロールバック

### 全件ロールバック

万一の事故時：

1. 適用前バックアップCSVを準備
2. 既存除外リストを全件「d」でCSV作成
3. バックアップCSVを「n」でCSV作成
4. 段階的に適用

### 部分ロールバック

特定商品の除外を取り消す：

```csv
control,item_id,reason
d,SKU-001,除外解除（誤判定）
```

## 既存除外との衝突回避

### 古い理由が残っているケース

```
既存：n, SKU-001, "2023-12-クリスマス終了"
今回：（除外維持・理由変更したい）n, SKU-001, "2024-05-在庫切れ"
```

→ u（update）で理由を更新：

```csv
u,SKU-001,2024-05-在庫切れ
```

### 既存除外と今回新規が同じ商品

- 既存：除外されている
- 今回：別の理由で除外したい
- → u で理由を更新

## 月次の運用フロー

### Day 1（月初）
- 前月除外リストのレビュー
- 解除候補の抽出（在庫補充済み・季節到来等）

### Day 2-3
- 新規除外条件の判定
- 候補CSV作成
- 差分計算

### Day 4
- シミュレーション結果のレビュー
- 担当者・責任者承認

### Day 5
- CSVアップロード
- 適用確認

### Day 6（適用後）
- 24時間後のチェック
- ROAS変化のモニタリング開始

### Day 30（月末）
- 月次効果測定
- 翌月の方針決定

## CSVのバージョン管理例

```
rpp/
  ├── exclusion/
  │   ├── 2024-04-01_full.csv（月初の完全リスト）
  │   ├── 2024-04-08_diff.csv（差分）
  │   ├── 2024-04-15_diff.csv
  │   ├── 2024-04-22_diff.csv
  │   ├── 2024-04-29_diff.csv
  │   └── 2024-05-01_full.csv（翌月初の完全リスト）
  ├── changelog.md（変更履歴）
  └── README.md（運用ルール）
```

→ 「いつ何を変えたか」が後から追跡できる。

## 差分管理を簡略化する仕組み

### Excel/スプレッドシート活用
- 既存リスト・今回リスト・差分を列で並べる
- 関数で差分自動計算
- VLOOKUP・COUNTIFで重複チェック

### 専用ツール
- 大規模店舗では除外管理ツール開発も検討
- ネクストエンジン・WMS等との連携
- 在庫システムからの自動連携
