## 例2：季節終了商品の段階的除外（クリスマス商品）

### 前提
- 12月25日終了のクリスマス商品 50点
- 1月初週から段階的に除外

### スケジュール

| 日付 | 操作 |
|---|---|
| 12/26 | 即時：「再販無理確定」商品20点を除外 |
| 1/1 | 残りクリスマス専用商品30点を除外 |
| 1/15 | 売れ残り在庫の最終セール商品（除外解除） |
| 2/1 | 完全終売、商品削除へ |


## 例3：競合ブランド名キーワードの除外

### 前提
- 自社商品が競合ブランドXのキーワードに表示される
- 商標問題・無駄クリック

### 出力CSV（キーワード除外）

```csv

n,競合ブランドX,商標問題

n,競合ブランドZ,商標問題
```

### 注意

- 自社商品が競合検索結果に表示されない設定（楽天のRPP仕様）

## 例4：ROAS悪化商品の除外（実績ベース）

### 前提
- 過去30日のRPP実績CSVから抽出
- ROAS<2.0の商品を除外候補

### Pythonでの抽出例

```python
import csv

rpp_results = []
with open('rpp_report_last30days.csv', 'r', encoding='shift_jis') as f:
    for row in csv.DictReader(f):
        ad_spend = float(row['広告費'])
        revenue = float(row['売上'])
        if ad_spend > 0:
            roas = revenue / ad_spend
            if roas < 2.0:
                rpp_results.append({
                    'item_id': row['商品管理番号'],
                    'roas': roas,
                    'reason': f'ROAS_{roas:.2f}'
                })

# 除外CSV出力
with open('exclusion_low_roas.csv', 'w', encoding='shift_jis', newline='') as f:
    writer = csv.writer(f, lineterminator='\r\n')
    writer.writerow(['control', 'item_id', 'reason'])
    for item in rpp_results:
        writer.writerow(['n', item['item_id'], item['reason']])
```

### 注意
- 新商品（30日未満）はROAS判定に含めない（実績不足）
- 季節商品は時期判定を別途
- 戦略的に広告を打っている商品（ロス・リーダー）は除外しない

## 例5：完全リストアップロードの場合

一部の楽天運用では「上書き型」のCSVアップロードを行う場合がある。その場合：

### 出力CSV

```csv
control,item_id,reason
n,SKU-001,在庫切れ
n,SKU-002,粗利率5%
n,SKU-003,廃番予定
...
（全除外対象を「n」で列挙）
```

ただし「上書き型」だと既存リストが全消去される。差分管理（n/d/u）の方が安全。

## 除外管理のベストプラクティス

### 月次レビューのアジェンダ

1. 前月の除外件数・解除件数
2. 除外によるROAS変化
3. 解除すべき商品（在庫補充・季節到来）
4. 新規除外条件の見直し（しきい値変更）
5. 翌月のスケジュール

### 役割分担

| 役割 | 担当 |
|---|---|
| データ抽出 | 運用担当 |
| 判定・CSV作成 | 運用担当 |
| 承認 | 運用責任者 |
| アップロード | 運用担当 |
| 適用後確認 | 運用担当＋責任者 |

### KPI

- 広告費削減額／月
- ROAS改善（除外前→除外後）
- 無駄クリック率（在庫切れへの流入）
- 在庫切れクレーム件数

→ KPIを設定して除外管理を「成果が見える」運用に。
