# バリエーション軸の選び方

## 軸として展開すべきもの・別商品コード化すべきもの

### バリエーション軸 vs 別商品コードの判断基準

| 軸 | バリエーション軸推奨 | 別商品コード推奨 |
|---|---|---|
| カラー（同型） | ◯ | − |
| サイズ（同型・同実寸） | ◯ | − |
| 容量（同商品） | ◯ | − |
| セット数 | ◯（軸2-3） | △（軸4以上で別コード） |
| メンズ/レディース | × | ◯ |
| メンズ/キッズ | × | ◯ |
| 大人用/子供用 | × | ◯ |
| 旧モデル/新モデル | × | ◯ |
| 通常品/限定品 | × | ◯ |
| 国内向け/海外向け | × | ◯ |
| OEM/プライベートブランド | × | ◯ |

## バリエーション軸として展開する判断軸

### 同型同等の見た目違い・スペック違い
- カラー：同じ形・機能でカラーだけ違う
- サイズ：同じ商品の大きさ違い
- 容量：同じ中身の容量違い

### 親子関係が成立する
- 親商品（共通の世界観・機能）
- 子バリエーション（軸の値違い）

### 軸2〜3個まで
- 1軸：カラーのみ等
- 2軸：カラー×サイズ
- 3軸：カラー×サイズ×容量
- 4軸以上：管理破綻、別商品コード推奨

## 別商品コード推奨の判断軸

### 対象が違う
- メンズ vs レディース：実寸が違うため別商品
- 大人用 vs 子供用：用途・サイズ規格が違う
- ペット種類別：別商品

### 世界観・ブランドが違う
- 通常ライン vs 限定ライン
- 国内向け vs 海外向け（パッケージ・規格違い）
- B2B vs B2C

### モデル世代が違う
- 旧モデル vs 新モデル
- バージョン違い（V1、V2、V3）

### 法規制が違う
- 化粧品 vs 医薬部外品
- 一般食品 vs 機能性表示食品

## 軸の優先順位

複数の軸が候補にある場合、優先順位を決める：

### 1位：販売影響が最大の軸
- アパレル：サイズ＞カラー
- 化粧品：容量＞カラー
- 家電：モデルグレード＞カラー

### 2位：在庫管理上の負担が小さい軸
- 在庫差が大きい軸（売れ筋偏在）

### 3位：表示上重要な軸
- 顧客が選びやすさを求める軸

## 各軸の値数の最適化

### カラー
- 標準：5〜10色
- 売れ筋に絞ると：3〜5色
- フル展開：10〜20色

業界別：
- アパレル：5〜10色が標準
- 化粧品（リップ等）：10〜30色
- 雑貨：3〜5色

### サイズ
- アパレル：3〜5サイズ（S/M/L/LL）
- 靴：5〜8サイズ
- 雑貨：2〜3サイズ（S/M/L）

### 容量
- 化粧品：2〜3容量（30ml/50ml/100ml）
- 食品：1〜3容量
- 健食：1〜2容量＋セット数

## 軸を削減する基準

### 売上下位の値を削減
- 過去3ヶ月販売数が下位10%の値
- 在庫日数180日超の値
- 滞留入口に入っている値

### 業界平均から外れる値
- アパレルのXSサイズ：需要が偏る
- 化粧品の特殊カラー：流行依存

### 季節終了時の調整
- シーズン終わりに弱い軸を削減
- 翌シーズンに復活させるか判断

## 軸を追加する基準

### 市場ニーズの新規発掘
- 顧客から「○○サイズはありませんか」の問合せ多数
- 競合が展開している軸

### 新規ターゲット獲得
- メンズに男性ライン追加
- レディースにキッズ展開

### 季節限定追加
- クリスマス限定カラー
- 母の日限定パッケージ

## 商品コード分割の判断（別商品コード化）

### 判断1：実寸・規格が違うか
- メンズLとレディースLは実寸違う → 別商品コード
- 同じS/M/Lでも別の規格 → 別商品コード

### 判断2：JANが別か
- バリエーションごとに別JANを取得しているなら、システム上は別商品扱い

### 判断3：マーケティング軸が違うか
- 顧客が「異なる商品」と認識する → 別商品コード
- 「同じ商品の選択肢」と認識する → バリエーション軸

### 判断4：法規制が違うか
- 医薬部外品とコスメ → 別商品コード
- 機能性表示食品と一般食品 → 別商品コード

## 軸の重複を避ける

軸同士が独立していないと管理が複雑：

例：「サイズ」と「実寸」を別軸にする → 重複
- サイズMの実寸は確定（カラーで実寸が変わらない）
- サイズ軸だけで実寸が決まる

軸を直交させる（互いに独立した次元）ように設計。

## カラーバリエーションの落とし穴

### 似た色を別バリエーションにする
- 「ピンク」と「サーモンピンク」と「ローズピンク」を全部別軸 → 顧客が選べない
- 解決：「ピンク系」でまとめる、または1色に絞る

### 限定カラーを通常ラインに混ぜる
- クリスマス限定の赤を通常ラインに → 季節終了後滞留
- 解決：限定カラーは別商品コードに

## サイズバリエーションの落とし穴

### XSや4Lを「念のため」入れる
- 需要が極端に少なく、毎回滞留
- 解決：データを見て削除

### サイズ展開数を多くしすぎる
- S/M/L/LL/3L/4L/5L とすべて展開 → 上位3〜4サイズが売上80%
- 解決：標準サイズに絞り、特殊サイズは別ラインまたは予約販売

## 容量バリエーションの落とし穴

### 容量違いだけのバリエーション化
- 容量30ml/50ml/100mlで価格が単純比例
- メリット少なく、別商品コードでも良い
- 解決：「お試し30ml」「本品50ml」「徳用100ml」のように顧客視点で差別化

### 容量と他軸の組合せ
- 容量×カラー = 多軸化
- 容量はバリエーション軸でなく別商品コード化を検討

## 軸選びの最終チェック

- [ ] 軸2〜3個に収まる
- [ ] 100バリエーション超えていない
- [ ] 不要な軸を削減した
- [ ] 別商品コード化すべき軸を分離した
- [ ] 軸同士が独立している
- [ ] 各軸の値数が過剰でない
- [ ] 業界平均と乖離していない
- [ ] 在庫管理ツールで運用可能
- [ ] モール仕様に適合
