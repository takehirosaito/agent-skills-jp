# ジャンル別 SKU命名規則 実例6パターン

---

## 例1：化粧品ブランド「BRAND-NAME」

**前提**：
- スキンケア・メイクアップ・ヘアケアの3カテゴリ
- 容量違い・カラー違い・限定パッケージ
- 想定SKU総数：500〜1,000
- 出店モール：楽天・Amazon・Yahoo!・自社EC

**提案命名規則**：
```
BRD-[カテゴリ2字]-[商品型番4桁]-[バリエーション3字]
```

**サンプルSKU**：
| SKU | 意味 |
|---|---|
| BRD-SK-0001-30M | スキンケア商品0001 30ml |
| BRD-SK-0001-50M | 同 50ml |
| BRD-SK-0001-100M | 同 100ml |
| BRD-MK-0050-PK1 | メイクアップ商品0050 ピンク1 |
| BRD-MK-0050-PK2 | 同 ピンク2 |
| BRD-MK-0050-PK3 | 同 ピンク3 |
| BRD-HK-0100-30M | ヘアケア商品0100 30ml |
| BRD-SK-0001-XMAS | スキンケア商品0001 クリスマス限定 |

**桁数**：標準16文字、限定18文字

## 例2：アパレルブランド「Btn」

**前提**：
- メンズ・レディース・キッズの3対象
- カラー×サイズの2軸バリエーション
- 想定SKU総数：3,000〜5,000
- 出店モール：楽天・Shopify・ZOZOTOWN

**提案命名規則**：
```
BTN-[対象1字]-[カテゴリ2字]-[商品型番4桁]-[カラー2字]-[サイズ1-3字]
```

**サンプルSKU**：
| SKU | 意味 |
|---|---|
| BTN-L-AP-1500-BK-S | レディース アパレル1500 ブラック S |
| BTN-L-AP-1500-BK-M | 同 M |
| BTN-L-AP-1500-BK-L | 同 L |
| BTN-L-AP-1500-WT-LL | 同 ホワイト LL |
| BTN-M-AP-2000-NV-M | メンズ アパレル2000 ネイビー M |
| BTN-K-AP-3000-PK-110 | キッズ アパレル3000 ピンク 110cm |

**桁数**：18〜20文字

**注意**：
- メンズ・レディース・キッズは別商品コードの方が在庫管理が楽
- サイズは「S/M/L」の英大文字とキッズの数字（110cm 等）を区別

## 例3：食品ブランド「Foody」

**前提**：
- お菓子・調味料・ギフトの3カテゴリ
- 季節限定が多い
- 賞味期限管理重要
- 想定SKU総数：300〜500

**提案命名規則**：
```
FDY-[カテゴリ2字]-[商品型番4桁]-[シーズン2字]
```

**サンプルSKU**：
| SKU | 意味 |
|---|---|
| FDY-OK-0010 | お菓子 商品0010 通年 |
| FDY-OK-0010-SS | 同 春夏限定 |
| FDY-OK-0010-AW | 同 秋冬限定 |
| FDY-OK-0010-XMAS | 同 クリスマス限定 |
| FDY-CD-0020-GIFT | 調味料 商品0020 ギフトセット版 |
| FDY-GF-1000-OBON | ギフト1000 お盆 |

**桁数**：13〜17文字

**注意**：
- 賞味期限・原産国は商品マスタの別属性で管理（SKUに埋め込まない）
- 「ギフト版」と「通常版」は同じ型番でバリエーション軸 or 別商品コード

## 例4：家電ブランド「Atech」

**前提**：
- ドライヤー・電動歯ブラシ・スチーマー等
- モデル違い（Lite／Pro／Pro Plus）
- カラー違い
- 想定SKU総数：50〜150

**提案命名規則**：
```
ATC-[製品3字]-[グレード3-4字]-[カラー2字]
```

**サンプルSKU**：
| SKU | 意味 |
|---|---|
| ATC-DRY-LITE-WT | ドライヤー Lite ホワイト |
| ATC-DRY-STD-BK | ドライヤー 標準 ブラック |
| ATC-DRY-PRO-PK | ドライヤー Pro ピンク |
| ATC-DRY-PROPLUS-GD | ドライヤー Pro Plus ゴールド |
| ATC-TBR-STD-BK | 電動歯ブラシ 標準 ブラック |
| ATC-STM-PRO-WT | スチーマー Pro ホワイト |

**桁数**：14〜18文字

**注意**：
- グレード（Lite／STD／Pro／Pro Plus）の命名を体系化
- 製品（DRY／TBR／STM）も体系化
- メーカー型番（自社の純正型番）と紐付け

## 例6：健康食品ブランド「Health」

**前提**：
- サプリ・健康茶・健康食品の3カテゴリ
- 容量×セット数の2軸
- 機能性表示食品の届出番号管理
- 想定SKU総数：100〜200
- 定期購入が主軸

**提案命名規則**：
```
HLT-[カテゴリ2字]-[商品型番4桁]-[容量3字]-[セット2字]
```

**サンプルSKU**：
| SKU | 意味 |
|---|---|
| HLT-SP-0001-30P-1B | サプリ 商品0001 30粒 1袋 |
| HLT-SP-0001-30P-3B | 同 3袋セット |
| HLT-SP-0001-30P-5B | 同 5袋セット |
| HLT-SP-0001-90P-1B | サプリ 商品0001 90粒 1袋 |
| HLT-TE-0050-100G-1B | 健康茶 商品0050 100g 1袋 |

**桁数**：18〜20文字

**注意**：
- 機能性表示食品の届出番号は商品マスタの別属性で管理
- 「定期コース」と「単発購入」は同SKUで価格バリエーションで対応 or 別SKU

## 共通の運用ポイント

1. **半角英大文字＋数字＋ハイフン**で統一
2. **桁数固定**（カテゴリ2字・型番4桁等）でソート可能に
3. **30文字以内**でモール文字数制限内
4. **将来の軸追加に対応**できる構造
5. **既存SKUは原則変更しない**（モール検索順位・売上履歴）
6. **モール跨ぎ統一**（ネクストエンジン等のマスター連携）
7. **JANはSKUと別管理**（バリエーションごとに別JAN）
8. **軸の値マスタ**を別表で管理（カラー名・サイズ名）

## 命名規則の決定までの流れ

1. 自社の取扱範囲を整理
2. 必要な軸を洗い出し
3. 軸の値リストを作成
4. 命名規則のパターンを3つ提案（シンプル／標準／詳細）
5. 想定SKU数で桁数を決定
6. モール仕様適合を確認
7. 既存SKUとの整合性を確認
8. 段階移行プランの設計
9. 採用後の運用ルール明文化

## 採用後の運用ルール

### 入力規則
- 入力時のバリデーション（正規表現）
- 既存SKUとの重複チェック
- 自動採番ツールの活用

### 命名権限
- SKUの新規発番は1名 or 1チームに集約
- 命名ルールから外れる場合は事前承認

### マスタ管理
- 自社商品マスタを「真実の唯一の情報源」
- モール側は連携で自動同期
- 月次でモール間の整合性を監査

### 例外運用
- どうしても標準パターンに収まらない場合は別ルールを文書化
- 例外SKUは年次レビューで標準化を検討
