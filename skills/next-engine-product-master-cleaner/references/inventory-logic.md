# 在庫加減算ロジックの詳細

ネクストエンジンの在庫操作で最も事故が多いのが「商品マスタCSV経由の在庫数変更」。**通常の商品マスタCSVでは在庫を上書きしない**設計になっており、誤った操作で在庫が大きくズレる。

## 基本原則

### 在庫は加減算で更新される（推測される動作）

商品マスタCSVの `zaiko_su` 列は、多くの版で「現在庫との差分として加減算される」動作になっている。
- 現在庫100、CSVに `50` → +50 加算で 150 になる場合がある
- 現在庫100、CSVに `-50` → -50 減算で 50 になる場合がある
- 厳密な動作は版・設定・モード（在庫変更／実数値登録）で異なるため、**必ず公式ヘルプの最新仕様を確認**

### 在庫の安全な操作（推奨）

1. **管理画面の「在庫変更」**
   - 実数値登録モード：絶対値で在庫を上書き
   - 加減算モード：差分で在庫を増減
   - 用途に応じて選択

2. **管理画面の「入荷登録」「出荷登録」**
   - 仕入入荷 → 在庫増
   - 廃棄／返品 → 在庫増減

3. **専用CSVテンプレート**
   - 「在庫一括登録」など、在庫変更専用のCSVテンプレートを使う
   - 通常の「商品マスタ」CSVとは別のテンプレート

4. **API経由の在庫更新**
   - 在庫変更APIを使う
   - 厳密にどのモードで動作するかをAPIドキュメントで確認

## 危険な操作（事故源）

### 商品マスタCSV経由で在庫を変更

NGフロー：
1. 商品マスタCSVをダウンロード
2. Excelでzaiko_su列を編集
3. 商品マスタCSVをアップロード

結果：
- 仕様により「上書き」「加減算」が異なり、意図しない在庫値になる
- Excelで開いた時点で他列も破壊される可能性（0落ち等）

### 加減算と上書きの混同

- 「在庫を全商品100にしたい」と思って `100` を全行に入れる → 加減算なら現在庫＋100で大幅増
- 「在庫を半分にしたい」と思って数値を半減 → 仕様によりさらに減る／逆に増える

## 在庫連携のタイミング

- ネクストエンジン → 各モール：**約10分間隔**
- 各モール → ネクストエンジン：受注取込ベース（即時～数分）
- 在庫変動の流れ：
  1. モールAで1個売れる
  2. ネクストエンジンが受注取込（数分以内）
  3. ネクストエンジンの在庫が-1
  4. 約10分後、他モールB/C/Dの在庫も-1反映

### 連携の遅延リスク

- 同時刻に複数モールで同一商品が売れた場合、ダブル販売リスク（在庫1個に対し2モールで受注）
- 対策：安全在庫を設定する／高速回転商品は予約販売運用にする／在庫連携間隔短縮を検討（プラン依存）

## セット商品の在庫

### 設計

セット商品（set_flg=1）の在庫は、**子商品の在庫から算出**される。

例：
- 子A：goods_id=`PEN-RED`、在庫50
- 子B：goods_id=`PEN-BLUE`、在庫30
- 親：goods_id=`PEN-SET-RB`、set_flg=1、stock_goods_id指定で子A+子B構成
- 親の在庫：子の最小在庫を基準（30セット作れる）

セットが1つ売れると：
- 親 PEN-SET-RB の在庫：30→29
- 子 PEN-RED の在庫：50→49
- 子 PEN-BLUE の在庫：30→29
- 再計算：子の最小在庫は29 → 親の販売可能数も29

### セット商品で起きやすい事故

- 子商品の在庫を手動でCSV上書き → セット親の販売可能数も連動して変わる
- 子商品Aを単品でも販売している場合、Aの在庫はセット販売とも連動するため売り切れリスクが高い

## 在庫差分の検証

### CSV出力時点の在庫スナップショット

商品マスタCSVをダウンロードした瞬間の在庫は「その時点の値」。アップロード時の在庫と差分があれば加減算で事故る。

安全な検証：
1. 在庫変更前のCSVをバックアップ
2. 変更後のCSVをアップロード前にバックアップ
3. アップロード後の在庫を取得
4. （アップロード後の在庫）= （アップロード前の在庫）± （CSVの差分）が成立するか確認
5. 整合しなければ即時ロールバック

## 在庫の安全在庫設定

ネクストエンジンには「安全在庫数」（safety_stock等の項目）がある場合：
- 実在庫が安全在庫を下回ったら警告
- モール連携では「実在庫 - 安全在庫」を販売可能在庫として出す設計が可能（設定次第）

### 推奨設定

- 高速回転商品：安全在庫2-5（モール間遅延対策）
- 中速回転商品：安全在庫0-1
- 低速回転商品：安全在庫0

## 在庫実数値登録の手順（推奨）

1. ネクストエンジン管理画面 → 商品マスタ → 該当商品を検索
2. 「在庫変更」または「実在庫数登録」機能を選択
3. **実数値モード**を選択（加減算ではなく絶対値）
4. 変更後の在庫数を入力
5. 確認画面で変更前／変更後を比較
6. 確定
7. 約10分後、各モールに反映

## まとめ：在庫操作の鉄則

1. **商品マスタCSVのzaiko_su列はアップロード時に動作仕様を必ず確認**
2. **在庫変更は専用機能（在庫変更／実数値登録／API）で行う**
3. **アップロード前後で在庫スナップショットを取りバックアップする**
4. **テスト商品1件で動作確認してから本番反映**
5. **セット商品の子在庫変更は親在庫にも影響することを把握**
6. **安全在庫を設定してモール間遅延の事故を予防**
