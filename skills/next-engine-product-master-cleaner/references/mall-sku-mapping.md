# モール別SKU紐付けマッピング

ネクストエンジンは「ハブ」として複数モールと連携する。各モールのSKU命名規則と紐付ける必要がある。

## 楽天市場との紐付け

### 楽天側のSKU概念

- **商品管理番号**：楽天 normal-item.csv の主キー、32byte半角英数
- **商品番号**：表示用の商品ID
- **項目選択肢別SKU**：バリエーション毎のSKU（横軸選択肢×縦軸選択肢で1つのSKU）

### ネクストエンジン → 楽天 のマッピング

| ネクストエンジン | 楽天 |
|---|---|
| バリエーション親 goods_id | 商品管理番号（親） |
| バリエーション子 goods_id | 項目選択肢別SKU |
| daihyou_shouhin_code | 商品管理番号 |

### 連携の仕組み（推測される動作）

1. ネクストエンジンの「商品マスタ」に rakuten_item_code 列等で楽天の商品管理番号を保持
2. 連携設定で「ネクストエンジン goods_id ↔ 楽天 項目選択肢別SKU」のマッピングを保持
3. 楽天で受注 → 受注取込時にgoods_idに変換
4. ネクストエンジン在庫が変動 → 約10分後に楽天在庫に反映

### 楽天SKUの注意

- 半角英数＋ハイフン推奨
- 全角文字混入はトラブル元
- 項目選択肢のSKUと商品管理番号を別概念として扱う

## Amazon との紐付け

### Amazon側のSKU概念

- **item_sku（SKU）**：出品者が自由に決められる商品コード
- **ASIN**：Amazonが自動採番する商品識別子（マーケットプレイス共通）
- **親子ASIN**：バリエーション商品の親子関係

### ネクストエンジン → Amazon のマッピング

| ネクストエンジン | Amazon |
|---|---|
| バリエーション親 goods_id | parent SKU（item_typeが parent） |
| バリエーション子 goods_id | child item_sku |
| daihyou_shouhin_code | parent_sku |
| amazon_asin | ASIN（自動採番、紐付け用） |

### Amazon連携の注意

- **item_sku は一度作成すると変更不可**（新規SKU作成が必要）
- SKUとASINを分けて管理（SKUはネクストエンジン主導、ASINはAmazonが採番）
- 同一商品を複数SKUで出している場合（プライム用／非プライム用）、ネクストエンジン側で2行の商品マスタ＋同一stock_goods_idで在庫共有

## Yahoo!ショッピング との紐付け

### Yahoo!側のSKU概念

- **code**：商品コード（半角英数推奨）
- **option1-value-N / option2-value-N**：バリエーション値
- **product-code**：JAN

### ネクストエンジン → Yahoo! のマッピング

| ネクストエンジン | Yahoo! |
|---|---|
| 単品 goods_id | code |
| バリエーション親 | code（親） |
| バリエーション子 | code＋option1/option2の組合せ |

### Yahoo!連携の注意

- バリエーションの管理がモール側で複雑（オプション値の組合せ）
- ネクストエンジン側で子SKUを個別管理してから、Yahoo!側のオプション組合せに変換

## Shopify との紐付け

### Shopify側のSKU概念

- **Handle**：商品（Product）のURL用ID、自動生成されるが手動指定も可
- **Variant SKU**：バリエーション毎のSKU
- **Variant ID**：Shopifyが採番する内部ID
- **Variant Barcode**：JAN等

### ネクストエンジン → Shopify のマッピング

| ネクストエンジン | Shopify |
|---|---|
| バリエーション親 goods_id | Handle（または Product Title から自動生成） |
| バリエーション子 goods_id | Variant SKU |
| daihyou_shouhin_code | Handle（親Product） |
| jan | Variant Barcode |

### Shopify連携の注意

- HandleはURL用に英小文字＋ハイフン推奨（自動生成される）
- Variant SKUは自由命名
- Variant IDで内部紐付け（変更不可）

## 紐付けの実装方法

### 1. 連携アプリ／プラグイン

- 楽天連携：ネクストエンジン公式
- Amazon連携：ネクストエンジン公式（SP-API）
- Yahoo!連携：ネクストエンジン公式
- Shopify連携：ネクストエンジン公式アプリ または サードパーティ

### 2. SKU一致モード

- ネクストエンジン goods_id = 各モールSKU
- 完全一致が前提
- 表記ゆれ・大文字小文字違いで紐付け失敗

### 3. マッピングテーブルモード

- ネクストエンジン goods_id ≠ モールSKU でも、連携設定でマッピング保持
- 例：goods_id `TSH-001-BLK-S` ↔ 楽天 `TSHIRT01-BL-SM` を手動マッピング

### 4. JANベースの紐付け

- goods_idでなくJANで紐付け
- バリエーション毎にJANが必要（同一JAN複数SKUは事故源）

## 紐付け検査の手順

### Step 1：モール側のSKU一覧取得

| モール | 取得方法 |
|---|---|
| 楽天 | RMS：normal-item.csv ダウンロード |
| Amazon | セラーセントラル：在庫レポート → 全在庫レポート |
| Yahoo! | ストアエディタ：商品一覧CSV |
| Shopify | Admin：商品エクスポートCSV |

### Step 2：ネクストエンジン側の商品マスタ取得

CSVダウンロード → goods_id・モール別SKU列を抽出

### Step 3：突合

- ネクストエンジン goods_id がモール側SKU一覧に存在するか
- モール側SKUがネクストエンジン goods_id 一覧に存在するか
- 不一致リストを作成

### Step 4：不一致パターンの分類

| パターン | 原因 |
|---|---|
| 表記ゆれ（大文字小文字／全角半角） | データ入力ミス |
| ハイフン種違い（半角／全角） | コピペ事故 |
| 先頭0落ち | Excel経由 |
| 末尾空白 | コピペ事故 |
| 完全未紐付け | 新規商品をモール側だけ／ネクストエンジン側だけに登録 |

## 紐付け不一致の修正手順

### 軽微な表記ゆれ
1. 正規化ルールを決める（半角統一・大文字統一・ハイフン-(U+002D)統一）
2. ネクストエンジン側で goods_id を統一
3. モール側のSKUは原則そのまま（Amazonは変更不可）

### モール側SKUとネクストエンジンgoods_idの体系違い
1. マッピングテーブルを別途維持
2. 連携設定でマッピングモードを使う
3. 将来の新商品はSKU統一の体系で運用

### 未紐付け商品
1. ネクストエンジン側にあってモール側にない → そのモールで未出品
2. モール側にあってネクストエンジン側にない → 未取込（手動取込が必要）

## 共通の落とし穴

- **同一goods_idに対し複数のモールSKUを紐付けようとして衝突**：1対多はネクストエンジンの仕様で対応していない場合あり
- **モール毎にバリエーション構造が違う**：楽天は項目選択肢、Amazonは親子、Shopifyはvariantで、ネクストエンジン側で吸収しきれない場合は手動マッピング
- **モール側のSKU命名規則変更**：途中で変えると過去取込データとの整合が崩れる
