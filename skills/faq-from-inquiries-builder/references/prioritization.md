# 優先度設計

問い合わせ削減・離脱阻止の2目的に対し、限られたFAQ枠をどこから埋めるかを判断する。

## 評価3軸

| 軸 | 重み | 評価方法 |
|---|---|---|
| 頻度 | 高 | 直近3-6ヶ月の件数、増減傾向 |
| 売上影響 | 高 | 1件あたりの注文金額・離脱リスク・LTV影響 |
| 離脱阻止寄与度 | 中〜高 | 購入検討中の問い合わせか／購入後の問い合わせか |

## 4象限マトリクス

```
売上影響大
   │
   │   ②中：FAQ・社内マニュアルで標準化      ①最優先：商品ページ・カート手前へ
   │
   ├─────────────────────────────────────
   │
   │   ④低：個別対応                        ③中：FAQに記載、検索可能に
   │
   └──────────────────────────────────── 頻度高
```

### 象限①：頻度高×売上影響大 → 最優先
- 商品ページ最上部・カート画面・購入ボタン手前にQ&A配置
- 商品ページ写真・スペック表に情報を埋め込み、FAQ参照を不要に
- 例：「サイズ感」「アレルゲン」「配送日数」「返品可否」「対応OS」

### 象限②：頻度低×売上影響大 → 中（FAQ常設）
- ヘルプセンターに必ず常設、検索キーワードを意識
- 個別問い合わせ時に社内マニュアルで標準回答
- 例：「高額品の海外配送」「法人向け請求書発行」「特殊サイズの取扱」

### 象限③：頻度高×売上影響小 → 中（チャットボット中心）
- チャットボット自動応答で対応、ヘルプ記事に内部リンク
- カスタマーサポート負荷を下げる
- 例：「営業時間」「会員ログインできない」「ポイントの使い方」

### 象限④：頻度低×売上影響小 → 低（個別対応）
- FAQ化はせず、社内CRMの過去履歴で対応
- 必要に応じて社内マニュアルに「個別対応事例」として残す

## 売上影響の見積もり方

1件の問い合わせがもたらす売上影響を以下の観点で：

- **購入検討中の問い合わせか**：返答次第で購入する／離脱する
- **返品・キャンセル誘発か**：返答次第で返品が増減する
- **クチコミ・レビューへの波及**：満足度が公開評価に影響する
- **LTV影響**：リピート阻害／促進

例：
- アレルギー問い合わせ → 安心して買えれば購入、不安なら離脱（売上影響大）
- 営業時間問い合わせ → 営業時間がいつでも買い物自体は可能（売上影響小）

## 離脱阻止寄与度の見積もり

「FAQに書いてあれば購入していたか」を考える。

- 高：「サイズが合わなかったら？」「気に入らなかったら？」（購入の心理障壁）
- 中：「いつ届く？」「ラッピングは？」（購入決定後の確認）
- 低：「会員登録の方法は？」（購入とは独立した運用）

商品ページQ&Aは離脱阻止寄与度の高い順に並べる。

## 頻度の正規化

問い合わせ件数のカウント時の注意：

- 同一顧客から複数回の問い合わせは1件として正規化するか、内容ごとに分けるか決める
- シーズナリティを考慮（夏物・ギフト時期は問い合わせが増える）
- 表記揺れを統合（「サイズ感」「サイズ違い」「サイズが合わない」「サイズが大きい」→「サイズ」クラスタへ）

## 優先度スコアリングの簡易式

各クラスタに対し：

```
優先度スコア = 頻度（0-100に正規化） × 重み1（1.0）
            + 売上影響（0-100に正規化） × 重み2（1.5）
            + 離脱阻止寄与度（0-100に正規化） × 重み3（1.2）
```

スコアの高い順に展開先を割り振る。重みは事業特性で調整：

- 客単価が高い事業：売上影響の重みを上げる
- 新規獲得重視：離脱阻止寄与度の重みを上げる
- カスタマーサポート負荷削減重視：頻度の重みを上げる

## 「FAQ化しない」判断も重要

以下は公開FAQ化を見送る：

- 法的にグレー（薬機法・景表法に触れる効能訴求）
- 個別顧客の事情に依存する（個人情報を含む）
- 一時的なトラブル（システム障害・キャンペーン期間限定）
- 過去の対応が「悪手」だった事例
- 競合との比較情報（自社が不利になる）

これらは社内マニュアルに留めるか、ポリシーを見直してからFAQ化する。

## 効果測定指標

FAQを公開した後、以下を観測：

- 該当クラスタの問い合わせ件数推移（公開前後で3ヶ月比較）
- FAQページのPV／検索キーワード
- 商品ページQ&Aを設置した商品の転換率（CVR）変化
- チャットボットのデフレクション率（自己解決率）

効果が出ない場合：

- 検索性が悪い → ヘルプセンターのカテゴリ・タグ設計を見直す
- 顧客に届いていない → 商品ページ・カート・購入完了メールへのリンク追加
- 回答内容が分かりにくい → 文体・例示・図示を改善
