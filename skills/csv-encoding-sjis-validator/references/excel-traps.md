# ExcelでCSVを開くと壊れる罠と対策

CSVが「アップロードできない」「エラー出る」の大半は、ファイル自体ではなく **Excelで開いた瞬間に発生する**。Excelは「便利な解釈」を勝手にしてしまうため、CSVのバイナリレベルで内容が改変される。

## 罠1：JAN/管理番号の先頭0落ち

**発生**
- `0049012345678` をExcelが数値と解釈 → `49012345678` に変化
- 「商品管理番号 `0001` 〜 `0099`」が `1` 〜 `99` に縮む

**対策**
- 開かない（テキストエディタで開く）
- どうしても開くなら：データ → テキスト/CSV → 列の型を「テキスト」指定で取込
- セル先頭にシングルクォート `'4901234567894` でテキスト固定（保存時はクォート除去確認）

## 罠2：13桁JANの指数表記化

**発生**
- `4901234567894` を数値解釈 → `4.90123E+12` 表示
- 保存すると桁が失われる

**対策**
- 列を「テキスト」で取込
- セル表示形式を「数値」「文字列」に変えても、内部値は既に壊れている場合あり

## 罠3：日付の自動変換

**発生**
- `1-2` を「1月2日」に変換 → `1月2日` または `2024/1/2` で保存
- `2024-01-02` を `2024/1/2` に
- 商品コード `12-345` が「12月345日」エラー

**対策**
- 列を「テキスト」で取込
- ハイフンを含むコードは特に注意

## 罠4：ハイフン／ダッシュのオートコレクト

**発生**
- 半角ハイフン `-`（U+002D）が EN-DASH `–`（U+2013）や EM-DASH `—`（U+2014）に置換
- マイナス記号 `−`（U+2212）に
- 「商品名 - サブ説明」のハイフンが全角ダッシュに

**対策**
- ファイル → オプション → 文章校正 → オートコレクトのオプション → 「ハイフンをダッシュに」のチェックを外す
- 既に変換済みの文字を一括置換

## 罠5：機種依存文字のSJIS外への変換

**発生**
- `①` `②` `㈱` `髙` `﨑` などをSJISで保存しようとすると、Excelが「？」または近似文字へ変換、または保存ダイアログで「一部の文字が失われます」警告
- 警告を見ずに保存 → データ破損

**対策**
- 機種依存文字を事前置換（`①` → `(1)`、`㈱` → `(株)`）
- 人名漢字（髙﨑等）は本人確認のうえで代替（高崎）か、SJISのIBM拡張漢字領域に該当するか確認

## 罠6：CR+LF→LFへの変換

**発生**
- Excel for Mac やバージョン差で改行コードがLFのみで保存されるケース
- 楽天/Yahoo!（CR+LF推奨）にアップロードして「ヘッダー認識失敗」

**対策**
- 保存後、テキストエディタで改行コードを確認
- VS Codeなら右下の「LF」「CRLF」表示で確認・変更可能

## 罠7：BOM自動付与（UTF-8 CSVモード）

**発生**
- Excelの「CSV UTF-8 (コンマ区切り)」で保存 → BOM (`EF BB BF`) が自動付与
- 楽天SJIS要件のファイルにBOMが混入 → 1列目「商品管理番号」が認識されない

**対策**
- 「CSV (コンマ区切り)」（SJIS版）を選ぶ
- UTF-8で保存する必要があるならBOM無し対応のCSVエディタを使う

## 罠8：1行目末尾の改行喪失

**発生**
- Excel保存後、テキストエディタで開くと最終行に改行がない／逆に余計な空行がある
- モール側でレコード数不一致エラー

**対策**
- バイナリで末尾バイトを確認
- 一行追加・削除で整える

## 罠9：列の自動補完／削除

**発生**
- 完全空の列がExcel保存で消える
- ヘッダーだけある空列が「列数不一致」を引き起こす

**対策**
- モールテンプレートの列順を完全一致で保つ
- 空列にも何らかのダミー値を入れる（モール仕様に応じて）

## 罠10：セル内改行の扱い

**発生**
- 商品説明文に改行を含めると、Excelが `Alt+Enter` の改行を `LF` で保存
- そのセルがダブルクォートで囲まれていないと、次行が新レコードと誤認

**対策**
- 改行を含むセルは必ずダブルクォートで囲む
- セル内 `"` は `""` でエスケープ
- Excel保存後に正しくクォートされているか確認

## Excelに代わるツール

- **テキストエディタ**：VS Code、Notepad++、サクラエディタ、CotEditor。エンコード・改行を明示的に扱える
- **専用CSVエディタ**：Cassava Editor、CSVed、Modern CSV、Ron's CSV Editor。型を勝手に変換しない
- **コマンドライン**：`iconv`（エンコード変換）、`nkf`（日本語特化）、`dos2unix` / `unix2dos`（改行変換）
- **Googleスプレッドシート**：Excelより素直だがUTF-8/LFで出力されるためSJIS要件モールには変換が必要

## まとめ：CSVを安全に扱う5原則

1. **Excelで開かない**（編集が必要ならCSV専用エディタ）
2. **開く必要があるなら型を「テキスト」で取込**
3. **オートコレクトをオフ**にする
4. **保存後はバイト列で検査**（先頭3バイトでBOM、改行コード、機種依存文字）
5. **モール仕様（エンコード／改行／区切り）に合わせて再保存**
