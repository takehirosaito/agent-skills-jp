# CSV検証 ケース別実例集

## ケース1：楽天用CSVをExcelで開いて保存して破壊

入力：`rakuten-items-20260415.csv`

検査結果：
- エンコード：UTF-8 (BOM有) — `EF BB BF 22 E5 95...`
- 改行：LF のみ
- 機種依存文字：① ×3、㈱ ×2、髙 ×1（人名）
- 商品管理番号 `0049XX...` が `49XX...` に短縮された行：12件
- 価格列に `4.9E+03` の指数表記：3件
- 商品名に EN-DASH `–` 混入：8件

判定：楽天の要件 `SJIS / CR+LF` を満たさず。**Excelで開いて保存した強い痕跡**あり。

対応：
1. システムまたはメーカーから元データを再取得
2. Excelで開かず、VS Code + 拡張機能 Edit csv で確認
3. 機種依存文字を一括置換（① → (1)、㈱ → (株)）
4. 髙 は本人確認のうえ判断（戸籍上の正字なら残す／商品名なら「高」へ）
5. SJIS(CP932) + CR+LF で保存し直し、BOMを外す
6. 1行サンプルアップロードで動作確認

## ケース2：Amazonフラットファイル「項目数が一致しません」

入力：`amazon-flatfile-202604.txt`

検査結果：
- エンコード：UTF-8 (BOM無)
- 改行：LF
- 区切り：タブ（TSV）
- 列数不一致：12行
- 該当行の `product_description` 列にタブ文字 `\t` を含むセル
- セル内改行（LF）を含むがクォートで囲まれていない

判定：説明文編集時にタブを誤入力／コピペ由来のタブが混入。

対応：
1. 説明文内のタブを半角スペースに一括置換
2. 改行を含むセルはダブルクォート `"..."` で囲む
3. ダブルクォート自体を含むなら `""` でエスケープ
4. 修正後にAmazonの「在庫ファイルテンプレート（フラットファイル）」のバリデーション機能で再検査

## ケース3：Shopify CSVがUTF-8 BOM付きでインポート失敗

入力：`products_export.csv`

検査結果：
- エンコード：UTF-8 (BOM有)
- 改行：CR+LF
- 区切り：カンマ
- 1列目ヘッダー名 `Handle` の前にBOM 3バイト

判定：Excelの「CSV UTF-8 (コンマ区切り)」で保存したと推測。Shopify側でHandle列が認識されない／全行新規Handleとして処理される。

対応：
1. テキストエディタでファイルを開く
2. 「BOM無しUTF-8」で保存し直す（VS Codeなら下部の `UTF-8 with BOM` をクリック → `Save with encoding` → `UTF-8`）
3. 改行コードをLFに統一（Shopify標準）
4. 再インポート

## ケース4：Yahoo!ショッピング 商品CSVにSJIS外人名

入力：`yahoo-items.csv`

検査結果：
- エンコード：Shift_JIS(CP932)
- 改行：CR+LF
- 区切り：カンマ ✅
- SJIS外文字：`𠮷` ×1、`𠀋` ×1
- 出品者氏名欄、商品名欄ともに

判定：CP932で表現できないCJK拡張漢字。Yahoo!アップロードで「？」化または取り込み失敗の可能性。

対応：
- `𠮷` → `吉`、`𠀋` → `丈` に置換（人名なら本人確認後）
- どうしても本字を使いたい場合：UTF-8対応のオプションがあるか公式ヘルプで確認
- 改善されない場合：手入力で個別登録

## ケース5：CR+LFとLFの混在で行ずれ

入力：`mixed-newline.csv`

検査結果：
- エンコード：Shift_JIS(CP932)
- 改行：CR+LF ×450件、LF のみ ×8件
- 該当8件は途中で改行が混入したセル

判定：エディタAで作成→エディタBで部分編集→保存時に改行が混在。

対応：
1. テキストエディタで「すべての改行をCR+LFに統一」
2. VS Codeなら右下「LF」をクリックして「CRLF」に変更し保存
3. dos2unix / unix2dos コマンドで一括変換も可

## ケース6：GoogleSheetsからエクスポート→楽天で文字化け

入力：`Sheet1 - rakuten.csv`（GoogleSheetsで「CSVとしてダウンロード」）

検査結果：
- エンコード：UTF-8 (BOM無)
- 改行：LF
- 区切り：カンマ
- 機種依存文字：① ×2、㈱ ×1
- 商品管理番号列の先頭0は維持 ✅（Sheetsはテキスト保持）

判定：Sheets出力は素直だが、楽天要件 `SJIS / CR+LF` には変換が必要。

対応：
1. 機種依存文字を事前置換
2. テキストエディタで開き「Shift_JIS / CR+LF」で保存し直す
3. `iconv -f UTF-8 -t CP932 input.csv > output.csv` 等のコマンドでも可
4. 改行は `sed -i 's/$/\r/' output.csv` 等でCR+LF化（要追加検査）
5. アップロード前に1行先行確認
