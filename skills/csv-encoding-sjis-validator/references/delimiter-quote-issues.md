# 区切り・クォート崩れの典型と修正

CSV/TSVのアップロードで「列数が一致しません」「ヘッダーと本文の項目数が違います」「特定の行だけ無視される」エラーの大半は、エンコードではなく区切り・クォート崩れに由来する。

## 1. セル内のカンマ／タブ／改行

### 症状
- 商品説明文や注意書きに `,` や `\t` が含まれている
- そのセルがダブルクォートで囲まれていない
- → セルが2つ以上に分割され、列数が増える

### 例

```
SKU,商品名,説明
A001,スマホケース,iPhone13用、衝撃吸収,1980円
```

「衝撃吸収,1980円」の `,` で `説明` が2列になり、`A001` 行は4列 → ヘッダー3列と不一致でエラー。

### 対策

該当セルをダブルクォートで囲む：
```
SKU,商品名,説明
A001,スマホケース,"iPhone13用、衝撃吸収,1980円"
```

セル内に `"` 自体を含む場合は `""` でエスケープ：
```
A001,スマホケース,"商品名は ""スマホケース""です"
```

## 2. セル内改行の取り扱い

### 症状
- 商品説明にAlt+Enterで改行
- 保存時に行末LFがそのまま残る
- 1セルが2レコードと誤認される

### 例

```
SKU,商品名,説明
A001,スマホケース,軽量
で
頑丈,1980
```

「軽量で頑丈」が3行に分かれて見える。

### 対策

セル内改行を含むセルはダブルクォートで囲む：
```
SKU,商品名,説明,価格
A001,スマホケース,"軽量
で
頑丈",1980
```

ただし、改行を含めるとモール側のパーサーで事故るケースもあるため、説明文の改行は `<br>` タグ（HTML対応モール）またはスペースに置換が無難。

## 3. 区切り文字の混在

### 症状
- 拡張子は `.csv` だが中身はタブ区切り
- ヘッダーはタブ、本文はカンマ（編集ミス）
- Excelでタブをカンマに置換し忘れた

### 対策

ヘッダー1行と本文の最初5行で区切り回数を比較：
- カンマ数とタブ数の多い方を区切りと推定
- どちらも多数あれば「混在エラー」と判定

Amazonフラットファイルは**TSV（タブ区切り）**が標準。拡張子 `.txt` または `.csv` でも中身はタブ。

## 4. ダブルクォートの不一致

### 症状
- セルがダブルクォートで開いたまま閉じない
- パーサーが「次の `"` まで」を1セルと解釈 → 列が大幅にずれる

### 例

```
SKU,商品名,価格
A001,"スマホケース,1980
A002,タブレットスタンド,3500
```

A001のクォートが閉じておらず、A002までが1セル扱い。

### 対策

ダブルクォートの**奇数番目／偶数番目のカウント**を行単位で検査。奇数で終わる行は閉じ忘れ候補。

## 5. クォート内の `"` エスケープ忘れ

### 症状
- セル内容に `"` が含まれるのに `""` で重ねていない

### 例

NG：
```
A001,これは "テスト" です
```

OK：
```
A001,"これは ""テスト"" です"
```

### 対策

セル内に `"` を含むなら、必ずダブルクォートで全体を囲み、内部の `"` を `""` に置換する。

## 6. 列数の不一致

### 症状
- ヘッダー：30列
- 本文：行によって29列／30列／31列がある
- → モール側「項目数が一致しません」

### 検査方法

各行のカンマ（またはタブ）数をカウントし、ヘッダーと一致しない行を特定。列を分割した結果が空セルなのか、実データなのかで対応が変わる。

### 対策

- 空セルが原因なら、空でも区切り文字は残す（`,,,` のように連続カンマ）
- 余分な区切りが原因（セル内のカンマ）なら、該当セルをクォートで囲む

## 7. 末尾の空白／不可視文字

### 症状
- ヘッダー名が `商品管理番号 ` のように末尾に半角スペース付き
- BOMが先頭列名に混入
- 改行コードCRがヘッダーに残る
- → 列名が「未定義の列」と判定される

### 対策

- ヘッダー行をバイナリで先頭・末尾検査
- 各列名の前後 trim
- BOM除去

## 8. クォート文字の違い

### 症状
- 全角ダブルクォート `"` `"`（U+201C, U+201D）が混入
- シングルクォート `'` で囲む地域もある

### 対策

CSV標準のダブルクォートは半角 `"`（U+0022）のみ。全角クォートは事前置換または削除。

## 9. ヘッダー名の表記揺れ

| 揺れの例 | 正しい例 |
|---|---|
| `JAN コード` | `JAN` |
| `JAN_code` | `JAN` |
| ` 商品名 ` (前後空白) | `商品名` |
| `商品 名` (中間空白) | `商品名` |
| `ＪＡＮ` (全角) | `JAN` |

モール側のテンプレートと一字一句一致させる。

## 10. 列順の不一致

モールテンプレートは列順を厳密に決めている場合がある。順番が違うと「商品名」列に「価格」が入る等の大事故。

### 対策

- モール公式テンプレートをダウンロードし、ヘッダー行をそのまま使う
- 列の追加・削除はモールが認める範囲で

## 検査スクリプト例

```python
import csv

def diagnose(path: str, encoding: str = "cp932") -> dict:
    issues = []
    with open(path, encoding=encoding, newline="") as f:
        reader = csv.reader(f)
        rows = list(reader)
    header_len = len(rows[0])
    for i, row in enumerate(rows[1:], start=2):
        if len(row) != header_len:
            issues.append((i, len(row), header_len))
    return {"header_columns": header_len, "row_count": len(rows) - 1, "mismatches": issues}
```

これで列数不一致の行を特定できる。エンコードとクォート処理は `csv` モジュールが内部で扱う。
