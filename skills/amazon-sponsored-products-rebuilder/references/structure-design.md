# ポートフォリオ・キャンペーン階層設計

Amazon SP広告の効率的な階層設計。

## 階層の3層構造

```text
ポートフォリオ（戦略単位）
└── キャンペーン（戦術単位）
    └── 広告グループ（商品セット単位）
        └── ターゲット（KW・商品ASIN）
```

## ポートフォリオの設計

ポートフォリオは予算管理の単位。

### ポートフォリオの切り方

| 切り方 | 適する状況 |
|---|---|
| ブランド別 | 複数ブランドを管理 |
| カテゴリ別 | ブランド単一・カテゴリ多 |
| 商品ライン別 | シリーズが明確 |
| 季節別 | 季節商品が多い |
| 予算管理単位 | チーム別・KPI別 |

### 例：化粧品ブランドのポートフォリオ
- ブランドA - スキンケア
- ブランドA - ヘアケア
- ブランドB - スキンケア

### 1事業者あたりの推奨ポートフォリオ数
- 小規模：1〜3
- 中規模：3〜10
- 大規模：10〜30

## キャンペーンの設計

### キャンペーン分けの基本

| 分け方 | 例 |
|---|---|
| 種類（オート／マニュアル） | Auto / Manual |
| マッチタイプ | Manual-Exact / Manual-Phrase / Manual-Broad |
| ターゲット種別 | KW Manual / Product Manual |
| 商品グループ | 商品A群 / 商品B群 |
| 季節・期間 | 通年 / 季節限定 |

### 標準的なキャンペーン構成（1商品あたり）

```text
ポートフォリオ：[商品グループ名]
├── [商品グループ]Auto-探索
├── [商品グループ]Manual-Exact
├── [商品グループ]Manual-Phrase
├── [商品グループ]Manual-Broad
├── [商品グループ]Product-競合ASIN
└── [商品グループ]Product-カテゴリ
```

最低6キャンペーン。商品ライフサイクル次第で増減。

### キャンペーン名の付け方

統一規則：
```text
[ブランド略]_[商品グループ]_[種類]_[マッチ]_[備考]
```

例：
- BR1_VACUUM_Auto_探索
- BR1_VACUUM_Manual_Exact_メインKW
- BR1_VACUUM_Manual_Phrase_ロングテール
- BR1_VACUUM_Product_競合A

→ 一覧で並べたときに整理しやすい。

## 広告グループの設計

### 広告グループの役割
- 同じ入札水準のターゲットをまとめる
- 同じ商品の異なるバリエーション（色違い等）を入れる
- 同じ訴求テーマのKW群をまとめる

### 広告グループの推奨数

| 状況 | 推奨 |
|---|---|
| 単一商品の単純広告 | 1グループ |
| 複数商品のシリーズ | 商品別 or テーマ別 |
| 1商品で異なる訴求軸 | 訴求別グループ |

### 例：1キャンペーン内の広告グループ
キャンペーン「Manual-Exact」内：
- 広告グループ「機能訴求」：「コードレス掃除機」「ハンディクリーナー」
- 広告グループ「シーン訴求」：「マンション 掃除機」「車内 掃除機」
- 広告グループ「顧客属性」：「一人暮らし 掃除機」「高齢者 掃除機」

入札を訴求別に変えたい場合に有効。

## ターゲット（KW・商品）の設計

### KW ターゲット
- マニュアル完全一致：「コードレス掃除機」
- マニュアルフレーズ：「コードレス掃除機」（フレーズマッチ）
- マニュアル部分一致：「コードレス掃除機」（部分マッチ）

### 商品ターゲット
- 個別ASIN：競合上位の特定ASINに広告配信
- カテゴリ：競合の属するカテゴリ全体に配信
- カテゴリ + 価格フィルタ：「家電カテゴリで15,000円以上」等
- カテゴリ + ブランドフィルタ：「家電カテゴリで競合ブランドのみ」

## 階層設計の落とし穴

### 1. ポートフォリオが多すぎ
- 100超のポートフォリオは管理不能
- 統合できるものは統合

### 2. キャンペーンが多すぎ
- 1商品10キャンペーン超は典型的な過剰設計
- 6前後で十分

### 3. 広告グループの中身が混在
- 異なる入札水準のKWを同じグループに入れる
- 効率が悪い

### 4. 命名規則が無い
- 「キャンペーン1」「KW広告」のような曖昧な名前
- 一覧で並んだときに迷う

## 既存キャンペーンの再構築アプローチ

### Step 1：現状の棚卸し
- 全キャンペーン・広告グループ・KW を一覧化
- 各キャンペーンの目的を再定義
- 重複している配信を洗い出し

### Step 2：整理対象の選定
- 重複キャンペーン → 統合 or 一方停止
- 無実績キャンペーン → 停止 or 入札調整
- 意味のないキャンペーン → 削除

### Step 3：新構造の設計
- 上記の標準構造をベースに
- 既存の実績ASIN／KW を引き継ぐ

### Step 4：移行
- 一気に切り替えるとデータ蓄積がリセットされる
- 旧キャンペーンを停止せず、並行運用2週間程度
- 新キャンペーン安定後に旧を停止

## ポートフォリオ予算上限

ポートフォリオは予算上限を設定可能：
- 月間予算上限
- 超えると配信停止
- 想定外の使いすぎ防止

ただし「キャンペーン日予算 × キャンペーン数 × 30」より大きく設定する。

## 階層設計のアンチパターン

### 「1商品1キャンペーン」原則の誤解
- 1商品でも複数キャンペーンが必要（オート・マニュアル別等）
- 1キャンペーン1商品 = OK
- 1商品1キャンペーン = NG（種類別に分ける）

### 「すべての商品を1キャンペーンに」
- 大規模で逆に効率悪化
- 商品ごとに最低オート・Manual-Exactを分ける

### 「マッチタイプを混在」
- 1キャンペーンに完全一致・フレーズ・部分一致を混在
- 入札最適化ができない、結果ACOS悪化
- マッチタイプ別キャンペーンが定石

## 階層設計の見直しタイミング

| 頻度 | 内容 |
|---|---|
| 月次 | キャンペーン名・予算消化率 |
| 四半期 | 重複・無実績キャンペーン整理 |
| 半期 | 全体構造の見直し |
| 年次 | ポートフォリオ整理・大規模リファクタリング |

## ROI最大化の階層設計

ROI最大化のための階層原則：
1. 高ROIキャンペーンを階層分離して入札強化
2. 低ROIキャンペーンを別階層に分離して入札削減
3. ネガティブKWで重複配信防止
4. プレースメント入札調整で効率化
5. 日予算配分で機会損失防止
