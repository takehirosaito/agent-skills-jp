# LINE配信メッセージ形式

LINE公式アカウントから送れるメッセージ形式と、用途別の使い分け。

## 1. テキストメッセージ

最も基本的な形式。最大500文字（仕様変動の可能性あり、要確認）。

### 用途
- 短い告知
- お礼メッセージ
- リマインダー（クーポン期限・キャンペーン終了直前）

### 設計
- 通知文（冒頭36文字）にフックを置く
- 改行・空白行を入れて読みやすく
- 末尾にCTA（リンク）

### 例
```
【3日限定】夏物ALL30%OFFクーポン配布中

8/1〜8/3まで、店内全商品が30%OFFになるクーポンを配布中です。

▼クーポンを取得する
https://example.com/coupon

夏のお買い物にぜひお役立てください。

○○ショップ
```

## 2. 画像メッセージ

画像1枚のみ。テキストは付帯せず、画像内にメッセージを含めるか、後続のテキストブロックを併用する。

### 用途
- ビジュアル訴求が強い商品（アパレル・コスメ・食品）
- バナー形式の告知

### 設計
- 1080×1080 または 1200×628 推奨（アスペクト比は要確認）
- 画像内テキストは20-30%以内（多すぎると読みづらい）
- ダークモード対応：背景を完全な白／完全な黒にしない、淡色を選ぶ

### 注意
- 画像オフ設定の友だちには見えない。テキストブロックでも補完する
- 画像URLが切れていないか配信前に確認

## 3. カードメッセージ（リッチメッセージ）

1枚のリッチカード。画像＋テキスト＋ボタンを1つにまとめた形式。

### 用途
- 商品1点を強く訴求
- イベント告知＋RSVPボタン
- LINE内ブラウザでの遷移

### 設計
- 画像：1040×1040（要最新確認）
- ボタン：1-2個まで
- ボタン文言：「クーポンを受け取る」「商品ページへ」「LINEで予約」など具体的

## 4. カルーセル（カード型）

複数枚のカードを左右スワイプで表示。3-10枚の商品を並べる。

### 用途
- 新作ラインナップ
- カテゴリ別のおすすめ
- ベスト3など

### 設計
- 各カードに画像＋商品名＋価格＋ボタン
- 1枚目はインパクトの強い商品（スワイプされなくても効果を出す）
- 順序：人気順・新着順・価格帯別

### 例
```
カード1：[人気No.1商品] 画像＋「夏のベストセラー」＋[詳細を見る]
カード2：[新作1] 画像＋「8月新作」＋[詳細を見る]
カード3：[セール商品] 画像＋「30%OFF」＋[詳細を見る]
```

## 5. クーポンメッセージ

LINE公式アカウント独自のクーポン形式。「取得」ボタンを押すと友だちがクーポンを保有、店舗QR読取り・コード入力で利用。

### 用途
- 新規友だち獲得時の特典
- 季節キャンペーン
- 休眠復活
- 誕生日特典

### 設計
- 割引額／割引率を明示
- 最低利用金額を明示（例：3,000円以上）
- 有効期限を明示
- 利用回数を制限（1回のみ／無制限）
- 利用可能な店舗・チャネルを明示

### 注意
- クーポンは自社EC・店舗で連動が必要（クーポンコード or QRコード方式）
- 期限切れクーポンを友だちが保有すると混乱
- 高額クーポンは在庫・利益率を確認した上で設計

## 6. リッチメニュー

LINEトーク画面下部に常駐するメニュー。タップで遷移する画像ベースのメニュー。

### 構成
- 6マス（2×3）または小さい（1マス・2マス）
- 各マスにテキスト・リンク

### 用途
- 主要ページへの常時導線
- クーポン・問い合わせ・予約等の頻出機能
- 季節キャンペーン中央マスに目立つアイコン

### 設計
- 6マスの場合：左上・中央上・右上／左下・中央下・右下
- 季節で差し替える（夏物・冬物・セール期）
- 文字は短く（5-10文字）
- アイコン併用で視認性UP

### 例（アパレルEC）
| 位置 | テキスト | リンク |
|---|---|---|
| 左上 | NEW ARRIVAL | 新着 |
| 中央上 | RANKING | 人気ランキング |
| 右上 | SALE | セール商品 |
| 左下 | LOOKBOOK | コーディネート |
| 中央下 | COUPON | クーポン |
| 右下 | SUPPORT | 問い合わせ |

## 7. リッチビデオ

動画をプレビュー再生する形式。

### 用途
- 商品の使い方紹介
- ブランドストーリー
- 季節キャンペーンの動画
- インフルエンサー協業

### 注意
- 通信量が大きい、配信時間帯と容量を意識
- 動画は短く（15-30秒推奨）
- 自動再生時に音は出ない前提、テキスト・字幕で意味が通る設計

## 8. ステップ配信（友だち追加後の自動シナリオ）

友だち追加から経過時間に応じて自動配信されるシナリオ。

### 標準シナリオ例（新規友だち教育）

| Step | タイミング | 内容 |
|---|---|---|
| 1 | 追加直後 | ウェルカム＋初回クーポン |
| 2 | 3日後 | 人気商品ベスト5 |
| 3 | 7日後 | ブランドストーリー＋使い方 |
| 4 | 14日後 | リマインダー（クーポン期限） |
| 5 | 30日後 | 2回目購入特典 |

### 購入後シナリオ例

| Step | タイミング | 内容 |
|---|---|---|
| 1 | 購入翌日 | 配送完了予定 |
| 2 | 到着3日後 | 使い方ガイド |
| 3 | 到着14日後 | レビュー依頼（規約内） |
| 4 | 30日後 | 関連商品おすすめ |

### 設計の罠
- ステップ長すぎ → 途中で離脱
- メッセージが同じトーンの連続 → 飽き
- 全員一律 → セグメント分岐がない（CV見送り）

## 9. 1配信に組み合わせる例

1配信のメッセージブロック数（プラン上限内で複数組み合わせ可能）：

```
配信1（1ブロック）
[テキスト] 通知＋本文

配信2（3ブロック）
[テキスト] 通知＋導入
[画像] バナー画像
[クーポン] クーポン取得ボタン
```

ブロックが多いほど通数がかさむため、プラン上限と相談。

## 配信形式選択のフローチャート

```
配信目的は何か？
├── 緊急告知・短いリマインダー → テキストメッセージ
├── 1商品の強い訴求 → カードメッセージ
├── 複数商品の比較 → カルーセル
├── 特典の取得 → クーポンメッセージ
├── ビジュアル訴求が強い商品 → 画像 or 動画
├── 友だち追加直後の教育 → ステップ配信
└── 主要ページへの常時導線 → リッチメニュー
```

## 配信形式と効果指標

| 形式 | 主要KPI |
|---|---|
| テキスト | クリック率 |
| 画像 | クリック率＋ブロック率 |
| カード | ボタンクリック率 |
| カルーセル | スワイプ率＋カード別クリック率 |
| クーポン | 取得率＋利用率 |
| リッチメニュー | マス別タップ率 |
| ステップ配信 | Step別離脱率＋最終CV率 |

## 補足：BIMI／DKIM／DMARC との関係

メルマガではメール認証（BIMI／DKIM／DMARC）が重要だが、LINE配信ではLINEヤフー社のプラットフォーム認証がベース。なりすまし防止は公式アカウントの認証バッジ（青／緑）で担保される。
