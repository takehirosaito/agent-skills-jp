# セグメント配信設計

LINE公式アカウントのセグメント配信（オーディエンス機能）を活用すると、開封率・クリック率を上げ、ブロック率を下げられる。

## セグメント配信の基本属性

LINE Official Account Manager で配信時に絞り込める基本属性：

| 属性 | 内容 |
|---|---|
| 性別 | 男性・女性（推定） |
| 年齢 | 年代別（推定、10代-60代以上） |
| OS | iOS／Android |
| 地域 | 都道府県単位 |
| 友だち追加期間 | 6ヶ月以内／1年以内 等 |
| 友だち追加経路 | 検索／QRコード／URL／広告 等 |

これらは推定情報で、100%正確ではない。傾向としての活用。

## オーディエンス（カスタム）の活用

「オーディエンス」機能で、より細かいセグメントを作成できる。

### 主なオーディエンスタイプ

1. **ユーザーIDアップロード**：CRMから抽出したIDをアップロード
2. **クリックリターゲティング**：過去メッセージのリンククリック者
3. **インプレッションリターゲティング**：過去メッセージのインプレッション者
4. **チャットタグ**：手動・自動で付与したタグ
5. **追加経路**：友だち追加時の流入元
6. **予約配信オーディエンス**：特定の予約配信を受信した友だち

### CRMからの連携活用例

ユーザーIDアップロードで、CRMから以下のセグメントをLINEに連携：

- 直近30日購入者
- 直近90日購入なし（休眠候補）
- 累計購入金額3万円以上（VIP）
- 特定カテゴリ購入者
- 誕生月の友だち

これにより、メルマガと同様のCRMセグメント配信がLINEでも可能。

## セグメント別の訴求設計

### セグメント1：新規友だち（追加〜2週間）

| 項目 | 設計 |
|---|---|
| 通知文 | 「友だち追加ありがとうございます！初回限定[X]円OFFクーポン」 |
| 本文 | 自己紹介＋初回特典＋人気商品紹介 |
| CTA | クーポン取得→人気商品の閲覧 |
| 配信タイミング | 追加直後＋3日後＋7日後（ステップ配信） |

### セグメント2：既存友だち（直近購入あり）

| 項目 | 設計 |
|---|---|
| 通知文 | 「○○様におすすめの新作が入荷しました」（パーソナライズ感） |
| 本文 | 関連商品・新着・限定情報 |
| CTA | 新着ページ→カート |
| 配信タイミング | 週1-2回 |

### セグメント3：休眠友だち（直近3-6ヶ月未購入）

| 項目 | 設計 |
|---|---|
| 通知文 | 「お久しぶりです！[X]円OFFクーポン限定配布」 |
| 本文 | 復活特典＋人気商品＋ブランド近況 |
| CTA | クーポン取得→注目商品 |
| 配信タイミング | 月1-2回（過剰配信は逆効果） |

### セグメント4：購入直後（〜2週間）

| 項目 | 設計 |
|---|---|
| 通知文 | 「[商品名]のご購入ありがとうございます。使い方ガイド」 |
| 本文 | お礼＋使い方・お手入れ＋関連商品 |
| CTA | 使い方記事→レビュー投稿（規約内で） |
| 配信タイミング | 購入後2-3日、7日、14日（ステップ配信） |

### セグメント5：高単価顧客（VIP）

| 項目 | 設計 |
|---|---|
| 通知文 | 「VIP限定先行販売のご案内」 |
| 本文 | 先行販売・特別招待・優待 |
| CTA | 先行ページ |
| 配信タイミング | 月1回程度（特別感を保つ） |

### セグメント6：特定カテゴリ購入者

| 項目 | 設計 |
|---|---|
| 通知文 | 「[カテゴリ]の新作入荷！」 |
| 本文 | 該当カテゴリの新着・関連 |
| CTA | カテゴリページ |
| 配信タイミング | 入荷タイミング |

## クロスセル・アップセルのセグメント設計

過去購入カテゴリから、関連カテゴリへ誘導：

| 過去購入 | 推奨配信先 |
|---|---|
| クレンジング購入者 | 化粧水・美容液 |
| Tシャツ購入者 | パンツ・アクセサリー |
| プリンター購入者 | インク・用紙 |

CRMの購入データを用意できる場合、これらのセグメントを作成して配信する。

## セグメント設計の罠

### 罠1：絞りすぎて配信数が少なくなる
- 100人未満のセグメントは効果測定が難しい
- 配信に手間がかかる割にインパクトが小さい

### 罠2：セグメントが多すぎて管理崩壊
- セグメントの数だけ運用工数が増える
- 5-10セグメントが現実的な上限

### 罠3：オーディエンスの更新を忘れる
- CRMアップロード型オーディエンスは古くなる
- 月1回は更新サイクルを設計

### 罠4：セグメント名が分かりにくい
- 「セグメント_001」では何の集合か分からない
- 「直近30日購入_VIP_iOS」のように属性を含める

## A/Bテストの設計

セグメント内で2-3パターンの文面を試して効果検証する。

| パターン | 違い | KPI |
|---|---|---|
| A | 通知文「3日限定」 | クリック率 |
| B | 通知文「数量限定」 | クリック率 |
| C | 通知文「クーポン」 | クーポン取得率 |

セグメント内で配信先をランダム分割し、2-3パターンの結果を比較。

## セグメント運用の社内体制

| 役割 | 担当 |
|---|---|
| セグメント設計 | マーケティング担当 |
| CRMデータ連携 | データ／システム担当 |
| 文面作成 | コピー担当 |
| 配信実行 | 運用担当 |
| 効果測定 | マーケティング担当 |

小規模事業者では一人で全てを兼任。最小限「セグメント設計＋文面＋配信」のサイクルを月次で回すのが現実的。

## 効果測定指標

| 指標 | セグメント効果の見方 |
|---|---|
| 開封率 | セグメントが正しく機能していれば全配信より高い |
| クリック率 | 関連性が高ければ全配信より高い |
| クーポン取得率 | クーポン設計とセグメントの合致度 |
| クーポン利用率 | 取得後の購買行動 |
| ブロック率 | セグメントが合っていなければブロック増 |

セグメント別にこれらを記録し、効果の高いセグメント・効果の低いセグメントを判別する。

## セグメント配信の月次サイクル例

| 週 | 配信内容 |
|---|---|
| 第1週 | 全友だち：今月のテーマ紹介 |
| 第2週 | 既存・購入直後：新商品案内 |
| 第3週 | 休眠：復活クーポン |
| 第4週 | VIP：先行販売案内 |

これで月4配信、セグメント別の運用負荷も分散される。
