# 商品データCSV の主要列リスト

MakeShop の商品データCSV で扱う代表的な列を整理する。列名は MakeShop の表示名や英語キー名が混在することがあり、ここでは **役割ベース** で整理する。

仕様（列名・上限・必須）は変更されるため、最終的には **MakeShop 管理画面のCSV インポート画面・公式ヘルプ** で最新を確認すること。

## 必須列

| 役割 | 一般的な列名 | 内容 | 注意 |
|---|---|---|---|
| 商品コード | goods_id | 商品の主キー。半角英数 | 大文字小文字区別。後から変更しない |
| 商品名 | 商品名 | 商品の表示名 | 文字数上限あり |
| 商品分類 | 商品分類 / category | カテゴリ | 既存カテゴリと完全一致 |
| 販売価格 | 販売価格 | 税込／税抜は店舗設定 | 数値型 |
| 在庫管理区分 | 在庫管理区分 | する／しない | 「する」の場合は在庫数必須 |
| 公開／非公開 | 公開フラグ | 公開／非公開 | 必須 |

## 文字数の目安（一般則）

| 列 | 目安 |
|---|---|
| 商品名 | 80〜120字程度（MakeShop 仕様により異なる） |
| SEOタイトル | 28〜32字 |
| SEOディスクリプション | 80〜120字 |
| 商品説明（一覧用） | 200〜400字 |
| 商品説明（詳細） | 制限上限大きいが、本文構造ある記述で2,000〜5,000字程度 |
| フリースペース1〜10 | 各列の上限内（MakeShop 仕様による） |

実際の上限は MakeShop の管理画面・CSVガイドを確認すること。

## 列の必須性チェック

商品データCSVをアップロードする前に：

- [ ] goods_id がすべて埋まっている
- [ ] goods_id が半角英数・記号のみ（全角混入なし）
- [ ] goods_id に重複がない
- [ ] 商品名がすべて埋まっている
- [ ] 商品分類が既存カテゴリと一致
- [ ] 販売価格が数値（カンマや「円」が混入していない）
- [ ] 在庫管理区分が「する」の場合、在庫数が数値で埋まっている
- [ ] 公開／非公開フラグが指定値（「1」「0」「公開」「非公開」など店舗仕様）

## 列順序

MakeShop のCSV インポートは **列順序固定** の場合と **ヘッダ行で列名識別** の場合がある。

- 列順序固定の場合：ヘッダの並びを変えるとデータが別列に入る大事故
- 列名識別の場合：列順序は任意だが、ヘッダ名のスペルミスでアップロード失敗

最新の挙動は管理画面のCSVインポート画面の説明で確認。

## 商品分類（カテゴリ）の指定方法

MakeShop の商品分類はツリー構造で、CSVでは次のいずれかで指定する：

- **分類ID**：管理画面で発行された分類のID
- **分類名（パス）**：「親 > 子 > 孫」のような階層パス

どちらの方式かは店舗仕様による。**事前に管理画面で分類を作成済** でないとCSV側で新規指定しても失敗する場合がある。

## 価格・税の扱い

- 店舗共通設定で「税込表示」「税抜表示」を選んでいるため、CSV側の価格もそれに合わせる
- 軽減税率対象（飲食料品等）の商品は専用列で指定
- 二重価格表示（通常価格 → セール価格）は8週間ルール（直前8週のうち過半で実販売）を満たすこと

## 在庫の更新

- 在庫数CSVの一括更新は **差分** か **全件** かを管理画面で選ぶ
- 「在庫数を増減する」更新と「在庫数を上書きする」更新を区別。商品データCSVは通常「上書き」
- 在庫補充の現場運用では「在庫数のみのCSV」を別途運用するケースもある（仕様による）

## 後から変更してはいけない列

- **goods_id**：URLや過去の注文履歴・SEO評価に影響
- **商品分類**：パンくず・URL構造に影響（変更時は301リダイレクト計画）

これらを変更する場合は影響範囲を事前に整理し、SEO・受注運用への影響を確認してから実施。
