# 社内検証ワークフロー

フラットファイルを Amazon にアップロードする前後の社内検証ステップ。事故・売上ロス・カタログ汚染を防ぐためのフロー。

## フェーズ1：事前検証（オフライン）

### Step 1：テンプレートの最新化
- セラーセントラル「在庫＞商品登録＞カテゴリ／テンプレートのダウンロード」
- 対象カテゴリのテンプレートをダウンロード
- 既存テンプレートと差分確認（列名・必須／推奨・ENUM）
- バージョン取得日を記録

### Step 2：商品情報の社内集約
- 商品マスター（PIM）から該当商品を抽出
- 必須列：SKU・JAN・商品名・ブランド・カテゴリ・価格・在庫
- 推奨列：bullet・キーワード・画像URL
- 親子バリエーション設計（あれば）

### Step 3：本スキルでの一次検証
- 必須列の存在
- データ型・桁数・バイト数
- JAN／GTINチェックデジット
- 親子バリエーションの整合
- `item_type` のENUM違反

### Step 4：関連スキル連携

| 検証観点 | 関連スキル |
|---|---|
| JAN／GTIN | `jan-code-checker` |
| メイン画像 | `amazon-main-image-checker` |
| タイトル | `amazon-title-bullet-rewriter-jp` |
| bullet | `amazon-bullet-attribute-benefit` |
| キーワード | `amazon-search-term-builder-jp` |
| バリエーション | `amazon-variation-parent-child-audit` |
| 薬機・景表 | `yakki-keihyo-expression-check` |

### Step 5：社内レビュー
- 商品マネージャー・カタログ担当者・法務担当者のクロスチェック
- 価格設定の最終確認（粗利・販売手数料）
- 画像の最終確認（規定準拠）

## フェーズ2：テスト登録（先行アップロード）

### Step 6：テスト用1〜2行のサブセット作成
- 全件の代表として1〜2SKUを抽出
- 全列の代表値を含むこと
- 親子バリエーションがある場合は親＋子1〜2行

### Step 7：セラーセントラルへアップロード
- 「在庫＞アップロードによる一括商品登録＞ファイルをアップロード」
- 文字コードを正しく指定（UTF-8 / Shift_JIS）
- 処理レポートを取得

### Step 8：エラーレポートの確認
- エラー番号と該当行を確認
- 「赤」エラー（必須・致命的）を最優先で修正
- 「黄」警告（推奨・SEO関連）も可能な範囲で修正

### Step 9：テストSKUの実機確認
- 商品ページが正しく表示されるか
- カテゴリ・属性が意図通りか
- 画像が正しく表示されるか
- バリエーション選択UIが機能するか

## フェーズ3：本登録

### Step 10：修正反映後の全件CSV作成
- テスト時に発見したエラーパターンを全行に反映
- 列順・列名がテンプレートと一致しているか

### Step 11：本番アップロード
- 一度に大量（数百〜数千行）アップロードする場合は時間帯を選ぶ（深夜帯はサーバ重い）
- アップロード後のレポートを必ず取得
- エラー件数を確認

### Step 12：エラー再修正
- エラーが残っているSKUは個別修正
- 重要SKUからカタログサポートにケース起票（`amazon-catalog-conflict-ticket-builder` 参照）

## フェーズ4：登録後の確認

### Step 13：登録から24時間以内
- 商品ページの最終確認（タイトル・画像・bullet・カテゴリ）
- 検索結果に表示されるか
- 親子バリエーションの選択UI
- スポンサープロダクト広告の対象になったか

### Step 14：1週間後
- アクセス数・購入数
- レビュー（不適切なものがないか）
- ランキング位置

### Step 15：1ヶ月後
- セールスチャネル別のCVR
- 在庫切れ・補充タイミング
- A+コンテンツ／ブランドストアとの整合

## バックアップとロールバック

### バックアップ
- アップロード前のフラットファイルを必ず保存
- 既存ASINの上書き登録の場合、上書き前の状態をスクショ保存
- 大量変更時は社内アーカイブ（クラウドストレージ）に保存

### ロールバック
- アップロード後に大きな問題が見つかった場合：
  - 該当SKUの `quantity=0` にして販売停止
  - カタログ修正は別ファイルでの上書きで対応
  - ASIN単位での削除は基本不可（販売停止での運用）
