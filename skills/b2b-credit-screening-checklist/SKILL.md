# B2B 与信審査 チェックリスト

## 概要

B2B EC・卸取引で新規取引先の与信審査を行うためのチェックリストと、与信限度額/支払条件の設定方針を整理するスキル。会社実在性の確認・信用情報の観点・与信限度額・支払条件の段階設定・債権保全・定期見直しまでを設計する。回収不能リスクを下げつつ取引機会を逃さないよう、相手の信用度に応じて条件を段階的に設計する。最終的な与信判断は専門機関・自社方針・法務確認が前提。

## 最重要原則

**「まず会社の実在性（登記・所在地・代表者）を確認／信用度に応じて支払条件を段階化（新規は前払/少額枠から）／与信限度額を設定し超過を管理／債権保全の選択肢（前金・保証・与信保険）を持つ／定期的に見直す（信用は変化する）」**。最初から大口の掛け売りはリスクが高い。前払・少額枠から始め、実績に応じて条件を緩める。

## 知識ベース

審査の観点：

| 観点 | 確認内容 |
|---|---|
| 実在性 | 商業登記、所在地、代表者、事業実態、ウェブ/連絡先 |
| 信用情報 | 信用調査会社のレポート、決算/財務（入手可能なら）、取引実績/評判 |
| 取引条件 | 希望取引額、頻度、支払希望（前払/掛け） |
| 与信限度額 | 1取引・月間の上限。信用度と取引規模で設定 |
| 支払条件 | 前払 → 代引/一部前金 → 少額掛け → 通常掛け の段階 |
| 債権保全 | 前金、連帯保証、与信保険、ファクタリング等の選択肢 |

段階設計の例：新規は前払または少額与信枠から開始 → 支払実績を見て限度額/サイトを段階的に緩和 → 異常時（支払遅延）は枠を縮小。

> 与信判断・信用調査は専門機関/自社方針/法務の確認が前提。本スキルは審査観点の抜け漏れ防止。

## 処理フロー

### Step 1：取引先・希望条件の確認
- 取引先情報、希望取引額/頻度、希望支払条件、入手可能な信用情報
不明時は仮定を置いて明示。

### Step 2：実在性・信用の確認チェック
- 登記/所在地/代表者、信用情報、取引実績/評判の確認項目を提示。

### Step 3：与信限度額の設定
- 信用度と取引規模から限度額（1取引/月間）の目安を設計。

### Step 4：支払条件の段階設計
- 前払〜掛けの段階を提示し、初期条件と緩和の基準を定義。

### Step 5：債権保全と定期見直し
- 保全手段の選択、与信の定期見直し・支払遅延時のアラート/縮小ルール。

## 出力フォーマット

```
# B2B与信審査 チェックリスト：[取引先]

## 0. 前提（取引先/希望条件・仮定）
## 1. 実在性・信用 確認項目（チェックリスト）
## 2. 与信限度額の設定（1取引/月間）
## 3. 支払条件の段階設計（初期→緩和基準）
## 4. 債権保全の選択肢
## 5. 定期見直し・支払遅延時の対応
```

## 品質ゲート
- 会社の実在性確認を最初に置いたか
- 支払条件を信用度に応じて段階化したか
- 与信限度額を設定し超過管理を含めたか
- 定期見直し・遅延時ルールがあるか

## 注意事項
- 与信判断・信用調査は専門機関/自社方針/法務の確認が前提。本スキルは法的・専門的助言ではない。
- 個人情報/信用情報の取得・利用は法令・規約に従う。
- 取引先により条件を恣意的に変える場合も、合理的基準を持つ。
