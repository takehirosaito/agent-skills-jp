# STORES ネットショップの商品登録項目（BASEとの差分）

STORES は「ネットショップ」「予約システム」「POSレジ」「決済」などを横並びで展開しているサービス。ここでは「STORES ネットショップ」を対象とする。

仕様は変更されるため、最終的には STORES 公式ヘルプで最新を確認すること。

## BASE との位置づけの違い

| 観点 | BASE | STORES ネットショップ |
|---|---|---|
| 主要ユーザー像 | 個人作家・小規模ブランド | 個人〜中小事業者・実店舗併用 |
| 拡張モデル | Apps で機能追加 | 機能内蔵 + 一部オプション |
| POS連携 | 弱い | STORES POSレジと統合可 |
| 予約販売 | 予約販売Apps | 予約システム（独立サービス）と連携可 |
| デザインカスタマイズ | テーマ＋HTML/CSS編集 | テーマ＋ブロックエディタ |
| 越境EC | 海外販売Apps | 越境対応プランあり |

## STORES の商品登録項目（要点）

| 項目 | 内容 |
|---|---|
| 商品名 | 必須 |
| 商品説明 | HTML可 |
| 価格 | 必須 |
| 在庫数 | 必須 |
| 商品画像 | 複数枚 |
| カテゴリ | カテゴリ分け可 |
| バリエーション | 種類・サイズ等 |
| SKU | 商品識別子 |
| 公開ステータス | 公開／非公開 |

詳細仕様（画像点数の上限・カテゴリ階層・HTMLタグ範囲）は時期によって変動する。最終的には STORES 管理画面と公式ヘルプを確認する。

## プラットフォーム選定の目安

### BASE を選ぶケース
- 個人作家・少数SKU
- SNS（Instagram, X）からの流入が主軸
- デジタルコンテンツ販売や受注生産が中心
- とにかく無料でスタートしたい

### STORES を選ぶケース
- 実店舗があり POSレジと在庫を統合したい
- 予約システム（飲食・サロン・教室など）と連携したい
- 中規模以上（年商数千万〜）の運営でデザイン自由度を重視

### どちらでも可
- 既製品仕入販売・ハンドメイド販売：ストアの好みで選んでよい

## 出力時の注意

本スキルが「BASE / STORES どちらか不明」で呼ばれた場合：
- まず想定する商品ジャンル・運用形態を確認
- 確認が取れない場合は **BASE を仮定して初稿** を出し、冒頭「0. 前提整理」に「STORESの場合は項目名・上限が一部異なる」と明示
- 「ネットショップ用途以外（予約システム・POSのみ）」が想定される場合は、本スキルの対象外として注記
