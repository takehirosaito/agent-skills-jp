# Amazon DSP オーディエンス・ファネル 設計

## 概要

Amazon DSP（ディスプレイ/動画のプログラマティック広告）のオーディエンス設計とファネル戦略を整理するスキル。リターゲティング・各種オーディエンス・ファネル別配信・クリエイティブ面・計測を設計する。検索連動のスポンサー広告（`amazon-sponsored-products-rebuilder`）では拾えない「認知」「閲覧/カート離脱のリターゲ」「購入後の再購入」を、ディスプレイ/動画で補う設計図を出す。

## 最重要原則

**「ファネル（認知→検討→購入→再購入）で目的を分ける／リターゲは行動の鮮度（閲覧/カート/購入）で分けて訴求を変える／検索広告との役割分担を明確に／指標はファネルに合ったものを見る（認知はリーチ、下層はCVやROAS）／重複・過剰接触(フリークエンシー)を管理」**。DSPは「とりあえずリターゲ」では非効率。行動データの鮮度と段階で設計する。

## 知識ベース

オーディエンスの代表分類：

| 種別 | 例 |
|---|---|
| リターゲティング | 自社商品閲覧・カテゴリ閲覧・カート離脱・過去購入者 |
| インマーケット | 特定カテゴリを購買検討中 |
| ライフスタイル/興味関心 | 購買傾向に基づく層 |
| 類似(Lookalike) | 既存顧客に似た層 |

ファネル別の狙い：
- 認知：新規リーチ（インマーケット/ライフスタイル）、指標はリーチ/フリークエンシー
- 検討：閲覧リターゲ、競合比較訴求
- 購入：カート離脱リターゲ、背中押し
- 再購入：購入者へのクロスセル/リピート

検索広告との分担：検索＝顕在需要の刈り取り、DSP＝認知拡大と離脱回収・再購入。両者を補完で設計。

> DSPの運用要件・最低出稿・在庫・計測仕様は変動する。確定は Amazon Ads 公式/DSP担当に確認。

## 処理フロー

### Step 1：目的・商材・データの確認
- 目的（認知/CV/再購入）、商材、既存の検索広告状況、ブランド登録/ストアの有無
不明時は「ブランド登録済み・検索広告は運用中・離脱回収と認知を補う」を仮置きし明示。

### Step 2：ファネル設計
- 認知/検討/購入/再購入の各段に目的とKPIを割り当てる。

### Step 3：オーディエンス設計
- 各段に対応するオーディエンス（リターゲの鮮度別、インマーケット、類似）を構成。

### Step 4：クリエイティブ・フリークエンシー
- ディスプレイ/動画の使い分け、接触頻度の上限、訴求の出し分け。

### Step 5：計測と検索広告との分担
- ファネル別指標、検索広告との役割分担と予算バランス。

## 出力フォーマット

```
# Amazon DSP 設計：[ブランド]

## 0. 前提（目的/商材/既存広告・仮定）
## 1. ファネル設計（段→目的→KPI）
## 2. オーディエンス構成
   | ファネル段 | オーディエンス | 訴求 |
## 3. クリエイティブ・フリークエンシー
## 4. 計測指標
## 5. 検索広告との役割分担・予算バランス
```

## 品質ゲート
- ファネル別に目的とKPIが分かれているか
- リターゲを行動の鮮度で分けたか
- 検索広告との役割分担を明確にしたか
- フリークエンシー（過剰接触）を管理しているか

## 注意事項
- DSPの要件・仕様は変動。確定は Amazon Ads 公式/担当に確認。
- 効果の断定・誇大表現、薬機法/景表法に反する表現は避ける。
- プライバシー/データ利用規約を順守する。
