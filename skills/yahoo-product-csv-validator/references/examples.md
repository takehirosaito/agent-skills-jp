# Yahoo!商品CSV検証 ケース別実例

---

## 例1：UTF-8 BOM＋LF改行で全件エラー

**症状**：1,200行の商品データCSVをアップロード → 「ヘッダー行が認識できません」

**確認**：
- `file -I product.csv` → `charset=utf-8`
- 先頭3バイト `EF BB BF`（BOM）
- 改行 LF のみ

**対処**：
1. VSCodeで開き、右下「UTF-8 with BOM」をクリック
2. 「Save with Encoding」→「Japanese (Shift JIS)」
3. 「LF」→「CRLF」へ変更
4. 再アップロード

## 例2：列名スペルミス

**症状**：「列 `prices` は無効です」「列 `quanty` は無効です」

**原因**：Excel で過去テンプレを流用した際にタイポ。

**対処**：
- `prices` → `price`
- `quanty` → `quantity`
- 必ず半角・小文字・公式表記に合わせる

## 例3：name 全角75文字超

**原文**：
`【楽天1位獲得・送料無料・あす楽対応】高機能 撥水加工 撥油加工 抗菌防臭 速乾 通気性 軽量 メンズ レディース キッズ 兼用 折りたたみ 傘 雨傘 日傘 晴雨兼用 折り畳み傘 大きい コンパクト おしゃれ`

**計測**：全角約95文字 → 20文字オーバー

**修正案**：
`高機能撥水・防臭 軽量 折りたたみ傘 メンズ レディース 大きい おしゃれ 晴雨兼用 日傘 雨傘 コンパクト`（全角約50文字）

優先語：機能（撥水）→ 商品タイプ（折りたたみ傘）→ 対象（メンズ／レディース）→ 形容（大きい／おしゃれ／晴雨兼用）。
削除：他モール訴求（楽天1位／あす楽）、重複訴求（軽量・コンパクト）。

## 例4：code 重複（バリエーション混在）

**症状**：「商品コードが重複しています：A-001（3件）」

**原因**：色違い（赤／青／黒）を同一 code で登録しようとした。

**対処**：
- option-data CSV でオプション化（親 code は1本）
- 各色を別商品として登録するなら code を分割（A-001-RED／A-001-BLU／A-001-BLK）
- `sub-code` 列で内部バリエーション管理する手法もある

## 例5：JAN チェックデジット不一致

**症状**：「product-code が不正です：4901234567890」

**検算**（GS1標準・本体右端から3,1,3,1...の重み）：
- 本体：`490123456789`
- 右から：9, 8, 7, 6, 5, 4, 3, 2, 1, 0, 9, 4
- 重み：3, 1, 3, 1, 3, 1, 3, 1, 3, 1, 3, 1
- 積：27, 8, 21, 6, 15, 4, 9, 2, 3, 0, 27, 4
- 合計：126
- 126 mod 10 = 6
- CD = (10 - 6) mod 10 = **4**

→ 正しい code は `4901234567894`。入力末尾 `0` は不一致。

## 例6：オプションCSV孤立

**症状**：「オプションデータの商品コードが商品データに存在しません：B-099」

**原因**：商品データから B-099 を一度削除したが、オプションデータには残っていた。

**対処**：
- B-099 を商品データに復活させる、または
- オプションデータから B-099 の行を削除
- 親 code と子 option の整合性は**毎回両CSVを同時更新**するルールを社内で定める
