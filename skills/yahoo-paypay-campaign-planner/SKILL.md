# Yahoo!ショッピング PayPayキャンペーン設計

## 概要

Yahoo!ショッピングの販促は、ストア原資（ストアポイント・自社クーポン）とプラットフォーム原資（PayPayステップ・LYPプレミアム・5の付く日・プレミアムな日曜日・ゾロ目・超PayPay祭）を組み合わせて「トリプル（ストアポイント＋優良配送＋PayPayステップ）」を構築するのが定石。

本スキルは、月次の販促カレンダー、ストア原資の粗利インパクト、表記上の景表法リスク、KPI設定までを一気通貫で設計する。

## 最重要原則

**PayPay施策の還元率・条件は頻繁に改定される。具体率は計画書に焼き付けず「設計時点で公式を確認」を必ず明示する。** 「PayPayステップ最大○％」「5の付く日+○％」「LYPプレミアム+○％」の数値は変動が大きく、過去資料の数字を流用すると景表法の有利誤認リスクが発生する。本スキルでは、原資負担の整理・原則・運用枠組みを固め、具体率は **最新の公式ヘルプを確認** とセットで提示する。

- 2025年11月にYahoo!ショッピング評価基準が総合13点→10点に変更（店舗ランク評価ロジック影響）

## 処理フロー

### Step 1：販促目的とKPI設定
- 目的：新規顧客獲得／既存顧客のLTV／在庫消化／月商目標
- KPI：売上／粗利／CVR／客単価／新規率／リピート率／CPO／ROAS

### Step 2：原資マップ作成
`references/paypay-step-latest.md` の表に従い、利用する施策を以下に分類：
| 還元元 | 負担者 | 粗利検算に含めるか |
|---|---|---|
| 通常ストアポイント | ストア | 含める |
| 上乗せストアポイント | ストア | 含める |
| 5の付く日 上乗せ | PayPay／Yahoo! | 含めない |
| LYPプレミアム特典 | LYP側 | 含めない |
| PayPayステップ | PayPay | 含めない |
| ゾロ目クーポン | Yahoo!負担／ストア負担 両方あり | 確認のうえ判断 |
| 自社設定クーポン | ストア | 含める |

### Step 3：トリプル設計
- ストアポイント倍率（自社設定）
- 優良配送（注文+2日以内着／出荷遅延率5%未満／ストア都合キャンセル率2.5%未満）
- PayPayステップ最大達成顧客への訴求

### Step 4：3層商品設計
`references/three-tier-product.md` を参照：
- 赤字覚悟商品（CPO重視・新規獲得）
- 主力商品（粗利確保・売上柱）
- 高単価商品（LTV／客単価アップ）

### Step 5：月次カレンダー作成
- 5の付く日（5・15・25日）
- プレミアムな日曜日（月1）
- ゾロ目（11・22日）
- 超PayPay祭（不定期、年数回）
- 自社のメルマガ・LINE配信日
- 在庫補充・売り切れ予測

### Step 6：表記・景表法チェック
「最大○％還元」の数値は条件併記でクリアか。打消し表示の視認性確認。

### Step 7：粗利検算（自社原資のみ）
```
売価 - 仕入原価 - 自社ポイント原資 - 自社クーポン原資 - 配送料負担 - 広告費 - モール手数料 = 粗利
```

### Step 8：実装計画と確認日記録
公式確認日と確認した数値（PayPayステップ%等）を計画書に記録。

## 代表例

### 食品ストアの5の付く日 強化計画

目標：月商の20%を5の付く日に集中、新規顧客率30%

設計：
- ストアポイント：通常1倍 → 当日3倍（自社原資+2%）
- 自社クーポン：5,000円以上で500円OFF（自社原資、原資率推定 7-10%）
- 訴求：「5の付く日 最大○％還元（PayPayステップ最大適用＋LYPプレミアム会員＋自店ポイント3倍）」※具体率は当日のYahoo!公式・PayPay公式・LYP公式で再確認

粗利検算（売価3,000円・原価1,500円の商品）：
- ストア原資2%（60円）＋クーポン按分（仮にCVRの20%が利用×500円=100円相当）＋配送負担300円＋広告費按分150円＋モール手数料（仮5%＝150円）＝ 760円
- 粗利 = 3,000 - 1,500 - 760 = **740円**（粗利率約24.7%）

確認日：YYYY-MM-DD（PayPay公式 / LYPプレミアム公式 / ストアクリエイターProヘルプ）

## 品質ゲート

- PayPay／LYP／5の付く日の数値は**設計時点の公式確認日**を記録しているか
- 「最大○％還元」表記に達成条件を必ず併記しているか
- 自社原資のみで粗利検算しているか（PayPay負担分を売上として誤計上していないか）
- 優良配送基準を満たしているか（満たさないとトリプル訴求が成立しない）
- 在庫切れリスクを織り込んだ販促量設計か

## エッジケース

- **PayPay施策の急な改定**：施策実施直前に率が変わるケースあり。前日に公式を再確認する手順を運用に組み込む
- **クーポン重複適用の挙動**：自社クーポンとYahoo!配布クーポンの重複可否は告知毎に異なる。利用条件を確認
- **新規ストアでPayPayステップが弱い**：自社単独施策（ストアポイント増額・クーポン）で補完しつつ、PayPay側の達成条件を訴求LPで案内
- **景表法の打消し表示**：「最大15%」の打消しが小さい・遠い・読みにくい場合は有利誤認とみなされ得る。文字サイズ・配置・色のコントラストを確保
- **2025.11の評価基準変更（総合13→10点）**：店舗ランクへの影響を確認し、優良配送・レビュー対応・配送品質を再点検

## 注意事項

- PayPayステップ／LYPプレミアム／5の付く日／プレミアムな日曜日の還元率・閾値・対象条件は頻繁に改定される。**設計時点で必ず公式ページを確認**する
- 過去の率や条件をテンプレに焼き付けると、改定後に景表法上の有利誤認リスクを生むため避ける
- 「最大○○％還元」訴求は達成条件併記＋打消し表示の視認性確保が必須
- 粗利検算では自社原資のみを引く。プラットフォーム負担分を売上に上乗せして計算しない
- 在庫切れによる失機・キャンセル増は店舗評価とトリプル成立に影響するため、販促量と在庫の整合を必ず確認
