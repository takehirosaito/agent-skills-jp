# bullet バイト計算ルール

## バイト数の数え方

Amazon の bullet バイト計算は UTF-8 ベースで考えるとほぼ実態に近い：

| 文字種 | バイト数 |
|---|---|
| 半角英数字（ASCII） | 1バイト |
| 半角記号（! @ # $ % など） | 1バイト |
| 全角英数字／全角記号 | 3バイト |
| ひらがな・カタカナ・漢字 | 3バイト |
| 半角カタカナ | 3バイト |
| 絵文字（Unicode上の絵文字） | 4バイト（実際は不可・除外） |

実務的に「全角＝3バイト・半角＝1バイト」で計算しておけばほぼ正確。

## bullet の上限

| 項目 | 上限 |
|---|---|
| 1bullet | 255バイト |
| 5bullet 合計 | 1,275バイト（理論上） |
| 検索インデックス対象（公式仕様） | 先頭1,000バイト |

実務目安：

| 全角換算 | バイト数 |
|---|---|
| 全角85文字 | 255バイト |
| 全角83文字 | 249バイト（249は generic_keywords の上限、bullet とは別） |
| 全角50〜80文字 | 150〜240バイト（推奨レンジ） |

## 半角と全角の混在計算

例：「【1.2kg軽量設計】両手で持つ必要のあった〜」

| 区間 | 内容 | バイト |
|---|---|---|
| 【 | 全角1字 | 3バイト |
| 1.2kg | 半角5字 | 5バイト |
| 軽量設計】 | 全角5字 | 15バイト |
| 両手で〜 | 全角各3バイト |  |

数値・単位を半角にすると、バイトを節約しながら可読性も上がる。
全角の「１．２ｋｇ」は11バイト、半角の「1.2kg」は5バイト → 半角推奨。

## 検索インデックス先頭1,000バイト

Amazon は bullet 全体ではなく**先頭1,000バイトのみ**を検索インデックスの対象にする（公式仕様、変更の可能性あり）。

戦略：
- 主要キーワードは **bullet 1番目** に最低1回入れる
- 全bullet を通じて、1,000バイト以内に主要KW・サブKW・関連KWを散らす
- bullet 5番目の末尾のテキストはSEO的に効きにくい → 安心要素や保証など「読まれる価値」優先

## 計算手順（実装的）

LLMで bullet のバイト数を概算する場合：

```python
def byte_count(text: str) -> int:
    """日本語/英数字混在テキストのバイト数を概算"""
    return sum(1 if ord(c) < 128 else 3 for c in text)
```

255バイトのチェックは：
```python
assert byte_count(bullet) <= 255
```

## バイト超過時の調整

1bullet が 255バイトを超えたら以下の順で削る：

1. 重複している言葉（「安心・安全・信頼できる」など）を1語にまとめる
2. 形容詞を削る（「とても」「非常に」「大変」は情報量ゼロ）
3. 数値の単位を半角化（１．２ｋｇ → 1.2kg）
4. 接続詞を切る（「〜です。〜です」を「〜・〜」に）
5. 一つのbullet に2情報入っているなら、片方を別bulletに移す（5項目内で再配分）

## 改行・特殊文字の扱い

| 文字 | 扱い |
|---|---|
| 改行（\n） | フラットファイルでは無視される／管理画面UIではエラー |
| HTML（<br>, <p>） | 不可（タグとしてそのまま表示される or エラー） |
| 絵文字（🎉⭐❤） | 不可（除外される or 文字化け） |
| 半角記号（・！？） | 可（バイト数1） |
| 全角記号（・！？） | 可（バイト数3） |
| 中黒「・」 | 区切り符として頻用、可 |
| ダーシ「—」「ー」 | 可、ただし用法統一 |
| 顔文字（(^_^) (T_T)） | 可だが避ける（ビジネス文体に合わない） |
| 機種依存文字（①②㊥㈱） | 表示崩れの可能性、避ける |

## 全bullet をまとめて検証する場合

5件すべてで以下を確認：

- [ ] 各bullet が255バイト以下
- [ ] 5件合計 が先頭1,000バイト以内に主要キーワードを含む
- [ ] HTML／改行／絵文字／URL／電話番号が一切ない
- [ ] 全角・半角の混在に違和感がない（特に数字・単位）
- [ ] 同じ属性が複数bulletで繰り返されていない
