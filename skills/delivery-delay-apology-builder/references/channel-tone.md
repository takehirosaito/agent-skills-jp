# チャネル別の謝罪トーン

謝罪文は通常の問い合わせ返信より「お詫びの深さ」が必要だが、過剰謝罪は逆に信頼を損なう。チャネル別の許容範囲を切り分ける。

## 楽天市場

### トーン
- 店長名義の親近感を保ちつつ、謝罪は丁重
- 「心よりお詫び申し上げます」「深くお詫び申し上げます」
- お祭り感（ポイントUP・買いまわり期間）の中での遅延は特に注意。期待値が高い

### 件名の付け方
```
【○○ショップ】ご注文商品のお届け遅延につきまして 心よりお詫び申し上げます（注文番号：xxxxx）
```

### 補償の運用上の注意
- 楽天規約：レビュー特典・過度な値引き・現金等価物の付与は違反点数の対象
- 次回利用クーポン・ポイント還元は楽天運営の規定内で
- 店外への誘導（自社EC・LINE登録）は規約違反になる場合

## Amazon.co.jp

### トーン
- 事務的・必要十分・簡潔
- 過剰な店長口調は避ける
- 「申し訳ございません」は1-2回で十分

### 件名の付け方
```
ご注文商品の配送遅延につきまして（注文番号：xxx-xxxxxxx-xxxxxxx）
```

### 補償の運用上の注意
- A-to-z 保証・チャージバックリスクを意識
- セラーセントラルのメッセージ機能経由が原則
- 外部URL・電話番号・メールアドレスをメッセージに含めるのは制限あり
- 配送パフォーマンス指標（出荷前キャンセル率・遅延出荷率・有効追跡率）に影響するため、遅延を放置しない

## Yahoo!ショッピング

### トーン
- 楽天と自社ECの中間
- 「ストア」名義で謝罪
- 親しみと事務性のバランス

### 補償の運用上の注意
- 優良配送・PayPayステップを意識（出荷遅延率5%未満、ストア都合キャンセル率2.5%未満）
- 評価への影響を意識した丁寧な対応

## 自社EC（Shopify／futureshop／BASE 等）

### トーン
- ブランドの世界観に揃える
- リピーターへの謝罪は別格で（顧客LTVが見えるため）
- カスタマーサポート担当者名を明記、責任者対応の場合は責任者名

### 補償の運用上の注意
- 自社ECは規約・運用が自由な分、補償の独自設計が可能
- 同梱品・手書きメッセージ・ブランドノベルティでの謝意表現が効果的
- ただし、補償ルールの社内文書化は必須

## LINE公式アカウント・チャット系

### トーン
- メールより短く
- 絵文字・記号は控えめ（謝罪に絵文字は不向き）
- 数行で結論＋次のアクション

### 例
```
[お客様名]様

ご注文商品の配送が遅れており、申し訳ございません。
配送業者に確認したところ、本日中に届く見込みとのことです。

万一間に合わない場合、キャンセル・全額返金も承ります。
ご希望をお知らせください。

○○ショップ
```

## 過剰謝罪を避ける目安

| パターン | OK | NG |
|---|---|---|
| 文中の「申し訳ございません」 | 1-2回 | 3回以上 |
| 「お詫び申し上げます」 | 件名と本文冒頭で各1回 | 段落ごとに繰り返す |
| 「深く」「心より」「謹んで」 | 状況の重さに応じて1回 | 全部つけて多重化 |
| 結びの謝罪 | 短く | 段落丸ごと謝罪文 |

過剰謝罪は「あえて重たく見せて補償回避」と取られる場合がある。誠実さは「短い謝罪＋具体的な対応」で示す。

## 顧客の感情段階に応じた語調

| 感情段階 | 顧客の状態 | 推奨トーン |
|---|---|---|
| 不安 | 「届きますか？」と問い合わせ | 安心感重視・状況明示 |
| 困惑 | 「予定が狂った」 | 共感＋代替案 |
| 不満 | 「対応が遅い」 | 丁寧＋早い対応の提示 |
| 怒り | 「いい加減にしろ」 | 責任者対応・規約に沿う |
| 諦め | 「もう要らない」 | 全額返金＋謝意 |

怒りの段階の顧客に「ご理解ください」「ご容赦ください」を使うと火に油。「ご不快な思いをおかけしました」と受け止め、対応を即時提示する。

## メッセージごとの「お詫び→具体策→締め」比率

謝罪文の構成比例：

- お詫び：20-25%（短く）
- 状況説明：20-25%
- 対応・期限：30-40%（最も重要）
- 連絡先・締め：10-15%

具体策が文面の3-4割を占めることが信頼回復の鍵。
