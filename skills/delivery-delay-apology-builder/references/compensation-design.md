# 補償の段階設計と判断基準

お詫び文の中で提示する補償は、状況に応じて段階を切る。担当者が独断で段階を上げない。

## 5段階モデル

### A：謝罪のみ（金銭補償なし）
- **適用シーン**：軽微な遅延（半日〜1日以内）、お客様の不便が限定的
- **内容**：文面でのお詫び・状況説明・到着見込みの明示
- **担当者判断**：可
- **目安**：到着自体は問題なく完了する、プレゼント用途などの時間的価値が高くない

### B：送料相当の補償
- **適用シーン**：2-3日の遅延、お急ぎ利用、配送日指定外し
- **内容**：
  - 次回利用クーポン（500-1,000円）
  - 当該注文の送料分返金
  - ポイント付与（楽天等で運営可能な範囲）
- **担当者判断**：可（金額上限を社内で決めておく）

### C：商品分の補償
- **適用シーン**：大幅遅延（5日以上）、誤配送、メーカー欠品でキャンセル
- **内容**：
  - キャンセル＋全額返金（送料含む）
  - 代替商品の優先発送（差額あれば事前確認）
  - 同等品の無償提供
- **担当者判断**：可（社内ルール内）／責任者確認推奨

### D：商品＋追加補償
- **適用シーン**：破損・誤配送・継続的なトラブル・SNS拡散リスクのある案件
- **内容**：
  - 交換品＋次回クーポン（1,000-3,000円）
  - 商品代金一部返金＋商品提供
  - 上位グレード品への無償アップグレード
- **担当者判断**：責任者承認必須

### E：個別対応（経営・法務判断）
- **適用シーン**：健康被害・PL責任・情報漏洩・行政照会・訴訟示唆
- **内容**：個別協議、金銭以外の対応も含む
- **担当者判断**：経営・法務・PL保険会社の判断必須

## 段階決定マトリクス

| 状況 \ 影響度 | 軽微（数百円分） | 中（数千円分） | 重（数万円〜） |
|---|---|---|---|
| 配送遅延（運送会社） | A | B | C |
| 配送遅延（店舗起因） | B | C | D |
| 欠品（メーカー） | A〜B | B | C |
| 誤配送 | C | D | D〜E |
| 商品破損 | C | C〜D | D |
| 健康被害訴え | E | E | E |
| 個人情報漏洩 | E | E | E |

## 補償の上限設計（社内目安）

担当者裁量で動かしてよい上限を事前に設計：

| 担当者裁量 | 例：1注文あたり |
|---|---|
| 一般担当者 | 1,000円相当まで（クーポン・送料返金等） |
| リーダー | 5,000円相当まで |
| 責任者 | 30,000円相当まで |
| 経営判断 | それ以上 |

これは目安で、各社の規模・客単価で調整する。

## 担当者が絶対に独断で言わないこと

- 「全額返金＋商品差し上げます」
- 「次回から半額で結構です」
- 「今後永久に送料無料で対応します」
- 「責任を取って辞めます」
- 「裁判を起こしてください」
- 「弁護士に連絡しても構いません」
- 「他のお客様にも同じ補償をしています」
- 「うちの規約に書いてあります」だけで終わらせる

## 補償提示の文例

### 送料返金
```
お詫びといたしまして、ご注文時の送料 [XXX] 円につきましては、
ご決済方法に応じてご返金させていただきます。
クレジットカード決済の場合：決済取消で[3-7]営業日以内に反映
銀行振込：別途振込先をお伺いいたします
```

### 次回利用クーポン
```
お詫びといたしまして、次回ご利用時にお使いいただける
[500/1,000/3,000]円分のクーポンを別途お送りいたします。
（有効期限：発行日より3ヶ月）
```

### 代替発送
```
お待ちいただいているお時間に変わるものではございませんが、
お詫びといたしまして、ご注文商品とあわせて[サンプル品／類似品/差額無償アップグレード]を
同梱させていただきます。
```

## 補償の前例化リスクとその回避

「前回のお客様には〜してもらえた」と次回のクレームで使われる。回避策：

- 補償の理由を明示（「初期不良のため」「誤配送のため」）し、特別対応であることを伝える
- 「今回は特別なご対応として」「お詫びのしるしとして」と一回性を示す
- ただし、毎回これを言うと逆に「いつも特別対応」になる。社内で補償基準を文書化

## PL責任が疑われる場合の特別ルール

「商品で体調を崩した」「ケガをした」と訴えがあった場合：

1. **担当者は独断で『補償します』と返答しない**
2. **担当者は独断で『責任はありません』とも返答しない**
3. 「事実関係を社内で確認のうえ、改めてご連絡」と一旦保留
4. 即時にPL保険会社（加入時）・法務・責任者へ報告
5. ロット番号・購入日・症状の詳細を聴取
6. 同ロット商品の出荷停止・他のお客様への注意喚起の必要性を判断
7. 必要に応じて行政（保健所・消費者庁）への報告

## 個人情報漏洩が疑われる場合の特別ルール

誤配送等で他人の個人情報が顧客に渡った可能性がある場合：

1. **即時責任者・情報セキュリティ担当へ報告**
2. 配送業者と連携した回収手配
3. 影響を受けた顧客への状況説明（事実のみ、推測しない）
4. 個人情報保護委員会への報告基準を確認
   - 不正アクセス・人為的漏洩・1,000人超等は報告義務あり
   - 軽微な誤配送1件でも記録は残す
5. 社内のインシデント記録に残す

担当者は独断で「漏れた」「漏れていない」を確定的に伝えない。

## 補償記録のフォーマット

CRMに以下を記録：

| 項目 | 内容 |
|---|---|
| 案件番号 | INC-2025-xxxx |
| 注文番号 | rakuten-xxxx |
| 顧客名 | （マスキング可） |
| 類型 | 遅延／欠品／誤配送／破損 |
| 原因 | 運送／店舗／天候／メーカー |
| 補償段階 | A／B／C／D／E |
| 補償内容 | クーポン1,000円／全額返金／代替発送 等 |
| 補償金額 | XXX円相当 |
| 承認者 | 担当者／リーダー／責任者 |
| 完了日 | YYYY-MM-DD |
| 再発防止アクション | （担当者・期日） |

四半期に1回、補償傾向を経営に共有し、構造的な問題（特定の運送業者・特定商品の破損率等）を可視化する。
