# 親子設計の典型パターン

カテゴリ別の親子バリエーション設計のベストプラクティス。

## パターン1：単一属性のバリエーション

### 例：醤油の容量バリエーション

```text
親：SOYSAUCE-PARENT
variation_theme: Size
├── SOYSAUCE-200ML（200ml）
├── SOYSAUCE-500ML（500ml）
└── SOYSAUCE-1L（1L）
```

### 適するケース
- 1つの軸でバリエーション
- 顧客の選択がシンプル
- 在庫管理がしやすい

### 設計のポイント
- size_name の表記を統一（「200ml」「500ml」「1L」と「200 ミリリットル」を混在させない）
- 表記は親と子で完全一致

## パターン2：色×サイズ（Combined）

### 例：シャツ

```text
親：SHIRT-PARENT
variation_theme: SizeColor
├── SHIRT-BLK-S（Black, S）
├── SHIRT-BLK-M（Black, M）
├── SHIRT-BLK-L（Black, L）
├── SHIRT-WHT-S（White, S）
├── SHIRT-WHT-M（White, M）
└── SHIRT-WHT-L（White, L）
```

### 適するケース
- アパレル全般
- 顧客が色とサイズの両方を選びたい

### 完全性の確認
- 全組合せ：2色 × 3サイズ = 6子
- 欠落なし、重複なし

### 在庫切れの扱い
- 1組合せだけ在庫切れの場合：quantity=0 にして販売停止
- 親子関係は維持

## パターン3：色×サイズ×幅（3軸）

### 例：靴

```text
親：SHOE-PARENT
variation_theme: SizeColorWidth
├── SHOE-BLK-23-R（Black, 23cm, Regular）
├── SHOE-BLK-23-W（Black, 23cm, Wide）
├── SHOE-BLK-24-R
├── SHOE-BLK-24-W
├── SHOE-WHT-23-R
├── SHOE-WHT-23-W
├── SHOE-WHT-24-R
└── SHOE-WHT-24-W
```

### 適するケース
- 靴・サイズ・幅・色のすべてが重要なカテゴリ

### 注意
- 子の数が多くなる（2×2×2=8子）
- 在庫管理・配送・撮影コストが増える
- 売れ筋を絞って組合せを限定する戦略も

## パターン4：フレーバー単一

### 例：シリアル

```text
親：CEREAL-PARENT
variation_theme: Flavor
├── CEREAL-CHOC（チョコ）
├── CEREAL-STRWBRY（ストロベリー）
└── CEREAL-PLAIN（プレーン）
```

### 食品の典型
- フレーバー違いを variation_theme=Flavor で
- 容量も違うなら SizeFlavor を検討

## パターン5：色×容量（コスメ）

### 例：口紅

```text
親：LIPSTICK-PARENT
variation_theme: ColorVolume （または同等のENUM）
├── LIPSTICK-RED-3G
├── LIPSTICK-RED-5G
├── LIPSTICK-PINK-3G
└── LIPSTICK-PINK-5G
```

### コスメの典型
- 色（口紅・アイシャドウ）とサイズ（容量）の組合せ

## パターン6：パッケージ数

### 例：歯ブラシ

```text
親：TOOTHBRUSH-PARENT
variation_theme: Count
├── TOOTHBRUSH-1PACK（1本入り）
├── TOOTHBRUSH-3PACK（3本入り）
├── TOOTHBRUSH-6PACK（6本入り）
└── TOOTHBRUSH-12PACK（12本入り）
```

### 適するケース
- まとめ買いオプション
- ギフトサイズの違い

## パターン7：ペットの種類別

### 例：ペットフード

```text
親：FOOD-PARENT
variation_theme: Size（実際にはペット種類）
├── FOOD-SMALL（小型犬用）
├── FOOD-MEDIUM（中型犬用）
└── FOOD-LARGE（大型犬用）
```

または

```text
親：FOOD-PARENT
variation_theme: TargetSpecies
├── FOOD-DOG-PUPPY
├── FOOD-DOG-ADULT
└── FOOD-DOG-SENIOR
```

### 適するケース
- 顧客の選択軸が動物・年齢

## パターン8：ベビー服のサイズ

### 例：ベビー服

```text
親：BABY-PARENT
variation_theme: Size
├── BABY-60（60cm）
├── BABY-70（70cm）
├── BABY-80（80cm）
└── BABY-90（90cm）
```

### 月齢ベースのサイズ
- 「60cm = 0-3ヶ月」など、サイズに月齢の目安を商品説明欄で

## 親子化しないほうがいい場合

### 1. 完全に別商品
- 例：「シャンプー」と「コンディショナー」
- セットで売るとしても、親子バリエーションは不適切
- セット商品として別ASIN

### 2. 機能が大きく違う
- 「掃除機」と「掃除機の互換バッテリー」
- 関連商品として別ASIN、商品ページの「関連商品」で連携

### 3. 価格帯が大きく異なる
- 「化粧水（2,000円）」と「化粧水セット（10,000円）」
- 親子化すると顧客の判断が難しくなる

### 4. ターゲット顧客が異なる
- 「メンズシャンプー」と「レディースシャンプー」
- それぞれ別ASIN で

## 設計のNGパターン

### 1. 親子の意味が違う
- 機能が違うものを親子化（例：「シャツ」と「Tシャツ」を親子化）
- 顧客は混乱

### 2. 子が多すぎる
- 10色×5サイズ=50子は管理困難
- 売れ筋を絞る、または別シリーズに分ける

### 3. 子が1つしかない
- 親子化する意味がない
- 単独ASINで運用

### 4. 親に画像なし
- 親ASIN の代表画像は必須
- 親に画像ないと検索結果で表示されない

### 5. variation 軸が明確でない
- 「ベーシック」「プレミアム」「デラックス」のような曖昧な軸
- 「素材」「機能」「容量」など具体的な軸に

## レビュー集約の設計

親子バリエーションのレビューは：
- 子に投稿されたレビュー → 親に集約
- 親ASINで全色・全サイズのレビューが見える
- レビュー★平均は親が計算

### 集約のメリット
- 早期に多くのレビュー件数
- 検索結果での評価表示が有利
- 顧客が安心して購入

### 注意
- 1色だけ品質悪い場合、その不満が全体に影響
- 色別・サイズ別のレビューも顧客は読み分ける

## メイン画像の設計

| 配置 | 内容 |
|---|---|
| 親ASIN | 代表色／代表サイズの画像（最人気のもの） |
| 子ASIN | 各バリエーションの画像 |

### 親の代表色選定
- 最も売れる色 or ブランドカラー
- 検索結果での視認性が高い色
- 後で変更可能

## 商品名（item_name）の設計

```text
親：[ブランド] シャツ メンズ 綿100% 4色展開 SS〜XL
子（黒S）：[ブランド] シャツ メンズ 綿100% Black, S
子（黒M）：[ブランド] シャツ メンズ 綿100% Black, M
...
```

→ 親は「全バリエーションを含むコンセプト」、子は「個別の色・サイズ」を明示。

## bullet の設計

- 親ASINで共通bullet（5箇条）
- 子ASIN ではbulletの再記入は不要（親から継承）
- ただし子個別の特性（特定の色だけの素材違い）があれば子に追加

## 価格戦略

### 同価格
- 全色・全サイズで同じ価格
- 一般的・運用が楽

### 異価格
- 大きいサイズだけ高い（例：XLは+500円）
- 限定色は高い（例：プレミアムカラーは+1,000円）
- 親子で価格列を別々に設定

## 在庫管理

- 子ASIN ごとに在庫管理
- 1色・1サイズだけ売り切れも普通
- 在庫切れ子の表示：選択肢で薄く表示される

## 新色追加・サイズ追加の手順

1. 新規子SKU を作成
2. parent_sku に既存親を参照
3. variation_theme は親と一致
4. JAN・価格・在庫を個別設定
5. フラットファイルでアップロード
6. 反映後の表示確認

→ 親ASINに新しい選択肢として表示される。
