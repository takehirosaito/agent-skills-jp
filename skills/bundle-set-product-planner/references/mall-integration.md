# モール別 セット商品登録の運用メモ

各モールの仕様は変更されるため、登録前に各モール公式ヘルプで最新情報を確認すること。

## 楽天市場

- **登録粒度**：SKUプロジェクト導入後はバリエーション項目（オプション）でセット数量違いを扱うか、別商品として登録するかを選択
- **セット商品の在庫**：構成品在庫とは別にセットSKU在庫を持つのが管理上わかりやすい。在庫管理ツール（ネクストエンジン等）で構成品連動引当を組む方法もあるが、自動連動の挙動はツール仕様による
- **検索・カタログ**：セット品独自のキーワード（「セット」「まとめ買い」「お試し」）をタイトル後半に入れる
- **JAN**：単品JANをセットに流用しない。セット用に新規JANを採番するか、JAN無しSKUとして運用
- **画像規定**：商品画像登録ガイドラインの枠線・テキスト割合制限を遵守

## Amazon

- **バンドル登録ポリシー**：単品としての販売実態と区別される「バンドル製品」として登録する場合、Amazonの「バンドル商品ポリシー」に従う。主要構成品が明確であること、バンドルとしての独自GTIN（または自社GTIN免除）が必要
- **バリエーション**：色・サイズ等のバリエーションとセット数量違い（3個入り／6個入り）は別軸で設計
- **FBA**：セット品をFBAで送る場合、外箱に「Do Not Separate」ラベル、Amazonの梱包要件を満たす
- **タイトル規定**：[ブランド名] [商品名] [パック数／セット数] のフォーマットを意識

## Yahoo!ショッピング

- **バリエーション**：カラー・サイズ・容量・本数 などをバリエーションで持てる
- **登録粒度**：バリエーション or 単独商品 の選択。セット数量違いはバリエーション、シーン同梱は単独商品が一般的
- **送料設定**：ストアの送料テンプレートに依存。送料込みプランの場合は商品価格に上乗せ

## Shopify（自社EC）

- **Bundle機能**：Shopify公式のBundles（旧Shopify Bundles）または「Shopify Bundles app」「Bold Bundles」等のサードパーティアプリ
- **在庫管理**：Bundlesでは構成品在庫の自動連動が可能
- **定期購入**：Shopify Subscriptions または Recharge / Bold Subscriptions 等のアプリで設定
- **特商法**：自社ECは特商法表示を自社で整える必要あり

## 在庫管理ツール（ネクストエンジン・らくらく在庫等）

- **セット品在庫の引当**：構成品の最少在庫からセット販売可能数を自動算出する機能あり
- **モール間共通在庫**：複数モール出店時、構成品が同時に複数セットに参加していると、優先順位設計が必要
- **JAN紐付け**：セット品独自JANと構成品JANの関係を正しく設定

## 価格表示の注意点（景表法）

- 「単品で買うより○○円お得」：単品価格の根拠（実際に8週間以上の販売実績）が必要 → 二重価格表示の8週間ルール
- 「通常価格○○円のところ、セットなら○○円」：通常価格の表示根拠が無いと有利誤認のリスク
- 「セット内容は予告なく変更する場合があります」を明示し、構成変更時にトラブルにならないように

## 特商法・薬機法・景表法の追加ポイント

- 定期購入バンドル：分量（個数・回数・期間）／総額／解約条件／申込期間 を最終確認画面で明示
- セット内に医薬部外品が含まれる場合：医薬部外品の承認効能を一般化粧品に拡大して表現しない
- 「お得」「半額」等は二重価格の合理性が必要
- 「No.1」「人気No.1」表記は根拠5項目（主体・期間・対象・方法・出典）必須
