# B2B EC 見積・価格テーブル 設計

## 概要

B2B EC・卸の見積書作成と価格テーブル（掛け率・数量階段・取引条件）の設計を支援するスキル。掛け率/卸価格・数量別の価格階段・MOQ・支払条件・送料/同梱・有効期限/但し書きを整理し、見積書の項目構成を出す。BtoC（小売）と異なる卸特有の論点を踏まえ、利益を守りつつ取引先が判断しやすい見積を設計する。

## 最重要原則

**「掛け率は粗利と取引規模で設計（安易な値引きをしない）／数量階段で大口を優遇しつつ採算ラインを割らない／MOQ・支払条件・送料負担を明記して後のトラブルを防ぐ／見積に有効期限と但し書きを必ず付す／価格表は小売価格との整合（販路保護）も意識」**。卸は1取引が大きく、条件の曖昧さが大きな損失や紛争につながる。条件を明文化する。

## 知識ベース

価格テーブルの構成要素：

| 要素 | 内容 |
|---|---|
| 掛け率/卸価格 | 上代に対する掛け率、または卸単価 |
| 数量階段 | ロット/数量帯別の単価（大口優遇） |
| MOQ | 最低発注数量/金額 |
| 支払条件 | 前払/代引/掛け（締め日・支払サイト）、与信は別途審査 |
| 送料/同梱 | 送料負担・無料条件、付帯（販促物等） |
| 見積条件 | 有効期限、納期、税の扱い、但し書き（価格改定・在庫状況） |

見積書の標準項目：宛先、件名、見積番号/日付、品目・数量・単価・金額、小計/消費税/合計、納期、支払条件、有効期限、備考、発行者情報。

> 価格・税務・取引条件は自社方針と税理士/法務確認が前提。本スキルは設計補助。

## 処理フロー

### Step 1：商材と取引条件の確認
- 商材・上代、想定取引先（規模/業態）、希望の掛け率方針、支払/送料の方針
不明時は仮定を置いて明示。

### Step 2：掛け率・卸価格の設計
- 粗利を確保する掛け率/卸単価を設定。採算ラインを提示。

### Step 3：数量階段とMOQ
- ロット/数量帯別の単価設計とMOQ。大口優遇と採算の両立。

### Step 4：取引条件
- 支払条件（与信は `b2b-credit-screening-checklist` 連携）、送料/同梱、納期。

### Step 5：見積書の項目構成
- 見積書のレイアウトと、有効期限・但し書き等の必須項目を提示。

## 出力フォーマット

```
# B2B見積・価格テーブル：[商材]

## 0. 前提（商材/上代/取引先・仮定）
## 1. 掛け率・卸価格（採算ライン）
## 2. 数量階段・MOQ
   | 数量帯 | 単価/掛け率 | 備考 |
## 3. 取引条件（支払/送料/納期）
## 4. 見積書 項目構成（有効期限・但し書き含む）
## 5. 留意点（販路保護・価格改定条項）
```

## 品質ゲート
- 掛け率が粗利と採算を踏まえているか
- 数量階段が大口優遇と採算を両立しているか
- MOQ・支払・送料・納期を明記したか
- 見積に有効期限・但し書きを付したか

## 注意事項
- 価格・税務・契約条件は自社方針と税理士/法務の確認が前提。
- 取引先ごとに条件を恣意的に変えると不公平・紛争の元。基準を持つ。
- 独占禁止法（不当な差別対価・拘束）等に触れる条件設定は避ける。
