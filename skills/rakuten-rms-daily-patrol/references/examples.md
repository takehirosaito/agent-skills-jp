# 実例：日次パトロールの運用パターン

## 例1：中規模店舗（商品数300・スタッフ3名）

### 日次パトロール（45-60分・1名担当）

#### 7:30-7:35：店舗トップ
- バナー期間確認
- お知らせ最終更新日確認
- 営業案内・配送案内

#### 7:35-7:50：商品ページ（売れ筋トップ15件）
- 表示崩れチェック
- 売り切れ表示
- レビュー新着確認

#### 7:50-8:00：RPP広告
- 配信状況・予算消化率
- CPC・ROAS確認
- 除外商品リスト更新検討

#### 8:00-8:10：在庫
- 警告水準（残5以下）の20件確認
- 補充計画との照合

#### 8:10-8:25：レビュー＋お問い合わせ
- 新着レビュー対応
- 未対応お問い合わせの処理開始

#### 8:25-8:30：違反点数・お知らせ
- RMSお知らせ確認
- 違反点数累積確認

#### 8:30：朝報共有
- Slackで前日異常＋本日重点共有

### 異常検知の例

| 検知 | 対応 |
|---|---|
| 売れ筋商品Aが残2 | 仕入担当に即連絡、明日入荷予定確認 |
| 商品Bの星2レビュー | CS担当が当日中に返信＋個別連絡 |
| RPP予算消化93% | 月末予算追加の判断、運用責任者に報告 |

## 例2：大規模店舗（商品数2,000・スタッフ8名）

### 分担パトロール（朝7-10時、複数名）

#### 7:00-7:30：システム担当
- 在庫CSV更新
- ネクストエンジン連携確認
- RMS APIアクセス確認

#### 7:30-8:30：運用担当2名
- 商品ページ表示崩れ（売れ筋トップ50件 × 2名）
- RPP広告詳細（カテゴリ別）
- イベント設定

#### 7:30-8:30：CS担当
- 新着レビュー全件
- お問い合わせ未対応案件
- 個別エスカレーション

#### 8:30-9:00：運用責任者
- 全担当からの報告集約
- 朝報作成
- 経営層への共有

#### 9:00：朝報配信
- 全員へSlack共有
- 重要事案は経営層メール

### 異常検知のフロー

```
パトロール担当が異常検知
  ↓
緊急度判定（基準による）
  ↓
緊急：即時 → 関連部門全員へ通知
高：当日中 → 担当者割り当て
中：翌日まで → タスクリストに追加
  ↓
朝報・週次レビューで進捗確認
  ↓
完了報告
  ↓
インシデントログ記録
```

## 例3：小規模店舗（商品数50・店主1名）

### 日次パトロール（30分・店主1名）

#### 8:00-8:05：店舗トップ
- 簡易確認

#### 8:05-8:15：商品ページ（全件or売れ筋）
- 表示確認
- 在庫状況

#### 8:15-8:25：RPP・お問い合わせ
- 簡易確認
- 急ぎ案件のみ対応

#### 8:25-8:30：違反点数・お知らせ
- RMS確認

### 小規模店舗の特徴
- 商品数が少ないため全件確認可能
- 異常検知は店主の経験による
- エスカレーション先がない（外部委託・コンサル）
- 自動化ツールへの依存度が高い

## 例4：大型イベント期間中（SS／マラソン）

### 通常パトロール＋追加運用

#### 朝（通常）
- 全項目を通常通り

#### 昼（追加）
- RPP予算消化確認
- 売れ筋商品の在庫状況
- 新着レビュー
- 緊急問い合わせ

#### 夕方（追加）
- 当日売上の中間確認
- 翌日への引き継ぎ
- 残予算の見通し

### イベント中の専用チェック

| 項目 | 頻度 |
|---|---|
| RPP予算消化 | 1日2-3回 |
| 在庫状況（売れ筋） | 1日2回 |
| クーポン利用枚数 | 1日2回 |
| 配送遅延の問い合わせ | 1日2回 |
| 競合価格・順位 | 1日1回 |

---

## 例5：連休明けの初日

### 通常の倍時間を確保

- 連休中の異常を一気にチェック
- お問い合わせの蓄積を優先対応
- 在庫・配送の遅延確認
- RPP配信状況の総点検

### チェック順序（優先度別）

1. 違反点数・楽天お知らせ（必ず確認）
2. 決済・売上の異常
3. 大量のお問い合わせ
4. 配送遅延クレーム
5. 在庫切れ
6. 通常パトロール

## パトロール記録の例

### 日報テンプレ

```
■ 日次パトロール記録

日付：2024-05-15（水）
担当：山田

【所要時間】
50分

【発見した異常】
- [緊急] 商品A 在庫切れ
  → 仕入手配済み、商品ページに「入荷待ち」表示
  → 担当：仕入担当、期限：本日中
- [高] 商品B 星2レビュー（配送遅延）
  → 返信＋個別連絡、配送業者調査
  → 担当：CS、期限：本日中
- [中] 母の日バナー残置
  → 通年版バナーに差し替え
  → 担当：制作、期限：明日

【共有事項】
- RPP予算 月末消化見込み 95% → 追加予算検討
- 楽天より違反点数アラート無し

【明日の継続確認】
- 商品A 入荷確認
- 商品B 配送業者からの回答確認
```

### 月次集計テンプレ

```
■ 2024年5月 日次パトロール集計

【パトロール実施】
- 実施日数：22日 / 営業日31日
- 平均所要時間：52分

【検知異常】
- 緊急：3件
- 高：18件
- 中：35件
- 低：12件

【再発した異常】
- 在庫切れ（同じ商品）：2件
- 配送遅延：5件

【対応完了率】
- 緊急：100%
- 高：100%
- 中：91%
- 低：75%

【課題】
- 在庫切れの再発 → 警告水準の見直し
- 配送遅延の継続 → 配送業者見直しを検討

【翌月へのアクション】
- 警告水準を残5→残10に変更（売れ筋商品）
- 配送業者A→Bへの切替検討
```

→ パトロール記録は「異常検知＋対応＋再発防止」のサイクルを回す素材。
