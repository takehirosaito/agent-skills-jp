# エスカレーション・通知運用

## エスカレーション基準

### 緊急度別の対応者・タイミング

| 緊急度 | 例 | 対応者 | タイミング |
|---|---|---|---|
| 緊急 | 違反点数35点／決済停止／人気商品在庫切れ／RPP配信停止 | 店長＋運用責任者＋関係部門 | 即時通知（15分以内） |
| 高 | 売れ筋商品在庫低下／低評価レビュー／配送遅延クレーム | 運用担当 | 当日中（朝/午後） |
| 中 | 期間表示の文言切替／季節商品の棚卸し | 運用担当 | 翌日まで |
| 低 | 設定見直し／写真リフレッシュ | 週次レビュー | 週次 |

### エスカレーション先

#### 階層別

```
パトロール担当（店舗運営）
↓
運用責任者（店長）
↓
事業責任者（EC事業部長）
↓
経営層（社長／取締役）
```

#### 内容別

| 内容 | エスカレーション先 |
|---|---|
| 違反点数・規約違反 | 法務担当・運用責任者 |
| 決済・売上トラブル | 経理担当・運用責任者 |
| クレーム・補償 | CS責任者 |
| 配送・倉庫トラブル | オペレーション責任者 |
| システム障害 | システム担当 |
| 法的トラブル | 法務・顧問弁護士 |

## 通知フォーマット

### 緊急通知テンプレ

```
🚨 緊急 [カテゴリ]

【内容】
[何が起きたか1-2行]

【影響】
[誰に何の影響があるか]

【現状対応】
[既に取った対応]

【追加対応必要】
[誰が何をすべきか]

【担当】[名前]
【期限】[時間]
```

### 例
```
🚨 緊急 [RPP]

【内容】
夏セールキャンペーンが予算枯渇で配信停止

【影響】
人気商品Aの広告流入が0、本日のCV30件減少見込み

【現状対応】
RMSで配信状況確認済み、予算追加検討中

【追加対応必要】
@運用責任者：予算追加の承認お願いします
@経理：本日中の予算追加申請

【担当】[山田]
【期限】本日10時まで
```

### 通常通知テンプレ

```
⚠️ 要注意 [カテゴリ]

[内容1-2行]
対応：[誰が何をするか]
期限：[時期]
```

## 朝報の運用

### 毎朝の朝報フォーマット

```
☀️ ○月○日 朝報

【前日異常】
- [カテゴリ] [内容] / [対応状況]

【本日の重点項目】
- [タスク1]
- [タスク2]

【今日のスケジュール】
- [イベント・社内タスク]

【共有事項】
- [楽天からのお知らせ等]
```

### 朝報の配信時間

- 平日：朝7時または8時
- 土日祝：当番制で朝9時

### 朝報の宛先

- 店舗運営チーム全員
- 関連部門（仕入・物流・CS）責任者
- 経営層（週1サマリで十分なケースも）

### 月次集計

- 緊急事案件数
- 平均対応時間
- 再発の有無
- 根本原因の傾向

→ 異常を「個別対応」で終わらせず、再発防止に組み込む。

## エスカレーションの判断軸

迷ったときの判断基準：

| 判断軸 | エスカレーションすべき |
|---|---|
| 違反点数・規約違反 | 法務・運用責任者 |
| 顧客個人情報の漏洩リスク | 即時、上長＋法務 |
| 決済・売上ロスが想定 | 経理＋運用責任者 |
| クレームが法的トラブル化の兆候 | 法務・顧問弁護士 |
| メディアに取り上げられた／取り上げられそう | 広報・経営層 |
| システム障害で店舗運営に重大な影響 | システム担当＋経営層 |

## 24時間対応の体制

### 平日・営業時間内
- 通常パトロール＋通知運用

### 平日・営業時間外
- 緊急のみ電話対応
- 朝一で対応する事案は明朝集中

### 土日祝・連休
- 当番制で1日1-2回パトロール
- 緊急電話対応
- 連休明けの初日は通常の2倍時間を取る

### 大型イベント期間（SS・マラソン）
- パトロール頻度を1日2-3回
- スタッフ増員
- 緊急対応のための待機

## 通知運用の継続改善

### 月次レビュー
- 通知件数・対応時間
- 通知が過剰・不足はないか
- ツール・フォーマットの見直し

### 四半期レビュー
- エスカレーション基準の妥当性
- 担当者の負荷分散
- 自動化できる項目の追加

### 年次レビュー
- 全体運用の効果測定
- 大規模な体制見直し

→ 「異常対応」を組織能力として磨いていく。
