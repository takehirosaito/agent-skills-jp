# 複数倉庫 在庫配分 設計

## 概要

複数倉庫（自社＋3PL、東西2拠点、モールのFC等）にまたがる在庫配分を設計するスキル。「どの拠点にどのSKUをどれだけ置くか」を、需要地への近接・送料ゾーン・リードタイム・拠点キャパ・欠品リスクのバランスで決め、SKU×拠点の配分マトリクスを出す。拠点間移送（横持ち）と安全在庫の置き方も整理し、過剰/欠品の偏りと無駄な横持ちを減らす。

このスキルは発注量の予測（`reorder-point-forecast-lite`）やアラート運用（`inventory-alert-action-list`）とは別で、「在庫を拠点間にどう割るか」に特化する。

## 最重要原則

**「需要地に近い拠点へ寄せて送料とリードタイムを短縮／回転の速いSKUは複数拠点、遅いSKUは集約／安全在庫は拠点ごとでなく全体最適で／横持ちコストと欠品コストを天秤に」**。拠点を増やすほど近接効果は出るが、在庫が分散して欠品しやすくなる。回転とリスクでSKUを分けて配分する。

## 知識ベース

配分を決める変数：

| 変数 | 内容 |
|---|---|
| 地域別需要 | 出荷先の地域構成（関東/関西/その他の比率） |
| 送料ゾーン | 拠点→配送先の送料・地帯区分 |
| リードタイム | 拠点→主要需要地の配送日数 |
| 拠点キャパ | 各倉庫の保管/出荷能力 |
| SKU特性 | 回転率・サイズ・単価・需要のばらつき |
| 横持ち | 拠点間移送のコスト・日数 |

配分の考え方：
- ABC×拠点：高回転(A)は需要地別に分散配置、低回転(C)は集約して在庫を持ちすぎない。
- 安全在庫は「拠点ごとに同じ量」ではなく、需要のばらつきと拠点役割で配分。
- 偏り（片拠点に在庫が寄って一方欠品）を定期的に是正（横持ち or 入荷振り分け）。

## 処理フロー

### Step 1：前提データの確認
- 拠点リストとキャパ、地域別出荷構成、送料ゾーン、主要SKUの回転率・サイズ
不明時は「東西2拠点・関東5割関西3割・高回転10SKU」を仮置きし明示。

### Step 2：SKUの分類
- 回転率・需要のばらつきでABC/分散-集約を分類。

### Step 3：配分マトリクスの作成
- SKU×拠点に推奨配分（比率/数量）を割り当て、近接・送料・キャパを反映。

### Step 4：安全在庫と横持ち方針
- 拠点役割に応じた安全在庫、欠品時の横持ち/相互補完ルールを設計。

### Step 5：是正ルール
- 偏り検知と入荷振り分け/横持ちの判断基準を定義。

## 出力フォーマット

```
# 複数倉庫 在庫配分：[事業者]

## 0. 前提（拠点/需要構成/送料・仮定）
## 1. SKU分類（回転×ばらつき → 分散/集約）
## 2. 配分マトリクス
   | SKU | 拠点A | 拠点B | 根拠 |
## 3. 安全在庫の置き方
## 4. 横持ち・相互補完ルール
## 5. 偏り是正の判断基準
```

## 品質ゲート
- 配分が需要地近接・送料・キャパを反映しているか
- 高回転/低回転で分散・集約を分けたか
- 安全在庫を全体最適で配分したか
- 横持ちコストと欠品コストを比較したか

## 注意事項
- 実データ（出荷地域・送料表・回転率）が精度を左右する。仮定は明示する。
- モールFC（FBA等）利用時は各サービスの在庫/手数料ルールを別途確認。
- 季節商材は需要シフトを前提に再配分を計画する。
