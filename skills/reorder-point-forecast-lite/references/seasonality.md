# 季節・トレンド調整

## 単純平均では精度不足のケース

直近30日平均日販で発注点を計算する標準的アプローチは、以下のケースでは精度不足：

1. **季節商品**：夏物・冬物・お正月・お盆 等
2. **イベント連動**：母の日・父の日・バレンタイン・ハロウィン 等
3. **トレンド変動**：SNSバズ・テレビ紹介・季節情報番組
4. **広告投下量変化**：広告強化期と通常期
5. **新商品リリース後の動向変化**：初期トレンドと安定期

## 季節商品の発注

### 年同期比較が原則
- 過去同月の販売実績を基準にする
- 「去年6月販売50個、7月150個、8月200個、9月80個」を当年予測の基礎に

### シーズン全体での発注計画
- シーズン開始前にまとめて発注 vs 段階発注
- 賞味期限・倉庫スペースで判断

### シーズン終盤の発注抑制
- 在庫過剰でシーズン後に滞留化
- 「シーズン終了予定日 − リードタイム × 2倍」を発注停止ライン

### 季節商品の例（年間スケジュール）

| 季節商品 | 主要シーズン | 発注タイミング |
|---|---|---|
| 夏物（水着・浴衣・冷感衣料） | 6〜8月 | 4〜5月発注 |
| 冬物（コート・ニット） | 11〜2月 | 9〜10月発注 |
| 母の日ギフト | 5月中旬 | 3月発注 |
| お中元 | 7月 | 5月発注 |
| お歳暮 | 12月 | 10月発注 |
| クリスマス | 12月 | 9〜10月発注 |
| お正月（おせち） | 12月末 | 9月予約開始 |
| バレンタイン | 2月14日 | 12月発注 |

## トレンド判定

### 直近期間の比較

```
直近7日／直近30日 比率 = 直近7日平均日販 ÷ 直近30日平均日販
```

- 1.2以上：上昇トレンド（急増）
- 0.8〜1.2：横ばい
- 0.8未満：下降トレンド

### 直近30日と長期の比較

```
直近30日／直近90日 比率
```

- 1.2以上：中期的に上昇
- 0.8未満：中期的に下降

### トレンド別の対応

**上昇トレンド**：
- 安全係数を高める（5%→1%）
- 発注量を多めに（適正在庫日数を長めに）
- 仕入先に状況共有・リードタイム短縮交渉

**下降トレンド**：
- 発注量を抑える
- 在庫過剰化に注意
- 滞留入口前に値引・販促検討

**横ばい**：
- 標準計算で発注

## トレンド検出の閾値設定

| 商品ジャンル | 上昇閾値 | 下降閾値 |
|---|---|---|
| 安定型（消耗品・日用品） | +20% | -20% |
| 変動型（アパレル・季節商品） | +50% | -30% |
| トレンド型（SNS連動商品） | +100% | -50% |

## 移動平均の活用

直近の販売変動を平均化して、ノイズを除去：

### 単純移動平均
```
7日移動平均 = 直近7日販売数 ÷ 7
30日移動平均 = 直近30日販売数 ÷ 30
```

7日と30日の比較でトレンド検出。

### 加重移動平均
直近に重みを置く：
```
加重移動平均 = (直近7日×3 + 8〜14日×2 + 15〜21日×1 + 22〜28日×1) ÷ 7
```

トレンドの転換点を早く捕捉。

## 異常値の除外

スポット的な大量注文（業者・イベント・キャンペーン）が日販に混入すると平均が歪む：

- IQR（四分位範囲）の1.5倍を超える外れ値を除外
- 「単発の大口受注」を別管理（在庫管理では考慮しない、または別フラグ）

例：日販が [3, 5, 4, 6, 50, 4, 5] → 50が異常値。除外して [3, 5, 4, 6, 4, 5] で計算。

## 広告投下量の影響

### 広告強化期
- 広告費を増やすと販売数が増える
- 発注は広告計画と連動
- 広告キャンペーン前に在庫増量

### 広告停止後
- 販売数が広告強化期から急減する可能性
- 停止後30日の平均日販で再計算

## 仕入先の制約

### 仕入先の発注締切
- 「毎週月曜12時締切、翌週金曜入荷」のような曜日サイクル
- 締切を逃すと1週間遅延

### 仕入先の休業
- 旧正月（中国）：1〜2月で2〜3週間休業
- 年末年始（日本）：12月末〜1月初
- お盆休み

仕入先のカレンダーを把握し、発注タイミングに反映。

## 季節調整係数

過去同月の販売傾向を係数化：

```
季節調整係数 = その月の平均日販 ÷ 年間平均日販
```

例：年間平均日販5個の商品
- 1月：3個 → 係数0.6
- 7月：8個 → 係数1.6
- 12月：12個 → 係数2.4

季節係数を発注点計算に乗じる：
```
季節調整後発注点 = 通常発注点 × 季節係数
```

## モバイル・PC比率の季節変動

通常時PC30%・モバイル70% → セール期（楽天スーパーセール等）はモバイル比率がさらに上がる傾向。
カートUI・配送サイズ・梱包資材の発注にも影響。

## イベント連動の在庫

### 楽天スーパーセール（年4回）
- 通常時の2〜3倍販売
- 1ヶ月前から在庫増量
- セール後の在庫過剰に注意

### ブラックフライデー・サイバーマンデー
- Amazon主導、楽天・Yahoo!も連動
- 11月末

### 母の日・父の日・敬老の日
- 1〜2ヶ月前から需要立上り
- ピーク当日の即配対応

### 季節カレンダー詳細は別スキル seasonal-sales-calendar-jp
- 月別・週別の販促カレンダー
- 業界別の販売ピーク

## トレンド予測の限界

本スキルは**過去データの統計処理**による予測。以下の予測は範囲外：

- 突発的なSNSバズ
- テレビ番組での紹介
- 競合の新商品リリース
- 自然災害・パンデミックの影響
- 法規制変更

→ 重要なトレンド要因はマーケ担当・営業との情報共有で補完。

## 季節商品の在庫廃棄ライン

季節商品で売れ残った場合：
- シーズン終了直後：30%引き販売
- シーズン終了1ヶ月後：50%引き／アウトレット移動
- シーズン終了3ヶ月後：処分検討
- 翌シーズン同時期：80%引きの福袋構成 or 廃棄

詳細は別スキル deadstock-clearance-planner
