# 到達率・配信認証（BIMI／DKIM／DMARC）

メールが受信者の受信トレイに届くか、迷惑メールフォルダに入るかは、ドメイン認証・送信者レピュテーション・コンテンツの3要素で決まる。

## ドメイン認証3兄弟＋1

### SPF（Sender Policy Framework）

送信元IPアドレスの正当性を検証する仕組み。

- DNSにSPFレコード（TXT）を設定
- 例：`v=spf1 include:_spf.google.com include:sendgrid.net ~all`
- 「このドメインから送信できるサーバー」を宣言

### DKIM（DomainKeys Identified Mail）

メール本文の改ざんを検出する電子署名。

- 送信メールにDKIM署名を付加
- 受信側がDNSの公開鍵で署名を検証
- 改ざんがあれば認証失敗

### DMARC（Domain-based Message Authentication, Reporting & Conformance）

SPF・DKIMの認証失敗時の処理ポリシーを定める。

- DNSにDMARCレコード（TXT）を設定
- 例：`v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com`
- ポリシー：none（観察のみ）／quarantine（迷惑メール扱い）／reject（拒否）

### BIMI（Brand Indicators for Message Identification）

認証済みメールの送信者トレイにブランドロゴを表示する仕組み。

- DKIM＋DMARC（quarantine/reject）が前提
- VMC（Verified Mark Certificate）を取得（年間費用あり）
- DNSにBIMIレコード（TXT）を設定
- 対応：Gmail、Apple Mail（iOS 16以降）、Yahoo!Mail 等

## Gmail／Yahoo! の新ガイドライン（2024年〜）

2024年に Gmail / Yahoo!Mail がメール送信者向けガイドラインを強化。日次5,000通超を送る送信者には以下が必須：

1. SPF・DKIM 認証通過
2. DMARC ポリシー（p=none 以上）の設定
3. 送信元ドメインのPTRレコード設定
4. メッセージヘッダ`List-Unsubscribe`に1クリック解除リンクを含める
5. 苦情率（迷惑メール報告率）0.3%以下を維持

ECで万人規模の友だちに配信する場合、これらは事実上必須。

## 送信者レピュテーション

ドメイン認証だけでは到達率は決まらない。送信者の振る舞い（レピュテーション）が重要：

| 指標 | 影響 |
|---|---|
| 苦情率（迷惑メール報告） | 0.3%超で大幅にレピュテーション低下 |
| バウンス率（無効アドレス） | 5%超でブロック |
| エンゲージメント（開封・クリック） | 高いほどレピュテーション向上 |
| 送信ボリュームの急増 | 急増は迷惑メール疑い |
| List-Unsubscribe対応 | 必須 |

### レピュテーションを上げる工夫

- リストクレンジング（バウンス率の低減）
- セグメント配信（関心高い人に絞る）
- 段階的な配信量増加（IPウォームアップ）
- 配信解除を簡単にする
- 開封・クリックの高いコンテンツを設計

### レピュテーションを下げる行動

- 古いリスト・買ったリストへの一斉送信
- バウンスを放置（無効アドレスを送り続ける）
- 解除リンクを分かりにくくする
- スパム的な件名・コンテンツ（過剰煽り）
- ドメイン認証の不備

## 迷惑メール扱いを避けるコンテンツ設計

### 件名で避けるべき要素

- 過剰な記号（!!!、￥￥、■■）
- 全大文字（FREE、URGENT）
- 「無料」「保証」「絶対」「完全」「No.1」の連発（薬機法・景表法にも触れる）
- 不自然な絵文字の多用

### 本文で避けるべき要素

- 画像のみで構成（テキストがない）
- 不自然なリンク（短縮URL、無関係なドメインへのリダイレクト）
- 過剰なHTML装飾（インラインスタイル多用）
- 送信者情報の不明確さ

### 望ましいコンテンツ

- テキストと画像のバランス
- 自社ドメイン直リンク（短縮URLを使わない）
- 配信解除リンクの明示
- 送信者情報・会社情報の完備

## 配信前のテスト

### 1. テスト送信
- 自社の Gmail / Yahoo! / Outlook / Apple Mail へ送信
- 受信トレイか迷惑メールか確認
- 表示崩れの確認

### 2. メールチェッカー
- Mail-tester.com 等の到達率診断ツールを使用
- スコア8/10以上を目標
- スコア低下の原因を確認

### 3. リンクチェック
- すべてのリンクをクリックして遷移確認
- リダイレクトの有無
- 404・期限切れページがないか

### 4. プレビュー
- スマホ／PCの両方で確認
- ダークモード対応
- 画像オフ時の表示

## 苦情率（Spam Complaint Rate）の管理

苦情率＝（迷惑メール報告数 ÷ 配信数）

| 苦情率 | 状態 |
|---|---|
| 〜0.1% | 健全 |
| 0.1-0.3% | 注意 |
| 0.3%超 | レピュテーション低下、Gmailの警告ライン |
| 1%超 | ブロック・配信停止のリスク |

苦情率が上がった場合：

- 直近キャンペーンのコンテンツ見直し
- 解除リンクを分かりやすく
- 配信頻度を下げる
- セグメントを絞る

## バウンス対策

| バウンス種別 | 対応 |
|---|---|
| ハードバウンス（存在しないアドレス） | 即時リストから除外 |
| ソフトバウンス（一時的な配信失敗） | 数回リトライ、続けば除外 |

バウンス率5%超は要対策。リストの鮮度を保つことが基本。

## ドメイン認証の設定確認手順

1. **SPF設定確認**：`dig TXT example.com` でSPFレコード確認
2. **DKIM設定確認**：配信プラットフォームの「DKIMレコード」をDNSに設定
3. **DMARC設定確認**：`dig TXT _dmarc.example.com` で確認
4. **配信後のレポート確認**：DMARCレポートを定期確認

## DMARCの段階的導入

最初はp=none（観察モード）で運用し、SPF/DKIMの認証状況を確認した後、p=quarantine（迷惑メール扱い）、最終的にp=reject（拒否）へ進める。

```
Phase 1（観察）：v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com
Phase 2（強化）：v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@example.com
Phase 3（厳格）：v=DMARC1; p=reject; rua=mailto:dmarc-reports@example.com
```

各段階で1-2ヶ月の運用観察を挟む。

## BIMI導入の費用感

- VMC（Verified Mark Certificate）：年間 約3-5万円〜
- 商標登録ロゴが必要（既存商標ロゴでOK）
- ロゴSVG形式の用意
- BIMIに対応していないメールクライアントには影響なし

BIMI導入によりブランド認知が上がり、開封率が向上する事例あり。中規模以上のECで検討価値あり。

## 配信解除の運用（特定電子メール法）

特定電子メール法に基づき以下が必須：

- 配信前にオプトイン取得（同意なしの配信不可）
- 配信解除のリンクを明示
- 配信解除後は配信停止（再送禁止）
- 送信者情報（会社名・所在地・連絡先）の明記

違反は措置命令、罰金（最大3,000万円）の対象。

## まとめ：到達率を上げる10原則

1. SPF・DKIM・DMARCを設定する
2. List-Unsubscribe対応する
3. 配信解除リンクを明示する
4. リストを鮮度を保つ（ハードバウンスを除外）
5. セグメント配信で関心の高い人に送る
6. 配信頻度を適切に保つ
7. 件名で過剰煽りを避ける
8. 画像とテキストのバランスを取る
9. 苦情率0.3%以下を維持
10. BIMI（中規模以上）で認知度向上
