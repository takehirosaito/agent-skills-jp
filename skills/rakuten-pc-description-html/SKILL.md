# 楽天PC商品説明文HTML生成

## 概要

楽天RMSのPC用商品説明文は10,240byte（全角5,120字）まで、HTMLタグの使用が可能です。本スキルは、ユーザーから提示された商品情報・差別化ポイント・画像構成・FAQをもとに、ファーストビュー・特徴・比較表・スペック・FAQ・クロージングのブロック構成でHTMLを生成します。

PC閲覧時の情報量を前提に、横長の比較表・複数列レイアウト・スペック表など、スマホでは使いにくい構成も活用。SP版とは別の説明文として独立設計します（同じHTMLの流用は禁止）。

## 最重要原則

**「PC版は横長レイアウト・比較表・複数列を活用してSP版と差別化／byte数10,240を厳守／重要情報は画像だけに依存させずテキストでも記載／SP版へのHTML流用は禁止」**。PCとSPは完全別の説明文として登録される。

## 知識ベース

PC版商品説明文の主要仕様：

| 項目 | 仕様 |
|---|---|
| 上限byte数 | 10,240byte（全角5,120字） |
| 文字コード | Shift_JIS(CP932) |
| 改行 | CR+LF |
| HTML可否 | 可（一部禁止タグあり） |
| 画像 | imgタグ利用可、外部URL参照 |

詳細：
- PC用説明文の仕様・利用可能HTMLタグ・禁止事項：`references/pc-spec.md`
- 推奨HTMLブロック構造（ファーストビュー・特徴・スペック・クロージング）：`references/html-blocks.md`
- 比較表・FAQの型バリエーション：`references/comparison-faq.md`
- ジャンル別PC説明文の実例4パターン：`references/examples.md`

楽天固有数値（必ず確認）：
- PC/SP説明文10,240byte（全角5,120字）
- 商品名255byte（全角127字）、キャッチコピー174byte（全角87字）
- 文字コードShift_JIS(CP932)・改行CR+LF
- 画像規定：700×700px以上推奨、テキスト占有率20%以内

## 処理フロー

### Step 1：商品プロファイル把握

ユーザーから以下を確認（不足時は仮定して進める）：

- 商品名・ブランド・主要スペック（サイズ・素材・成分）
- 競合との差別化ポイント3〜5個
- 商品画像のURLまたは予定構成
- 価格・送料・保証・配送条件
- よくある質問3〜7個
- 店舗トーン

不明な場合は「家電・差別化3点・FAQ5個・店舗トーン丁寧」を仮置きし冒頭で明示。

### Step 2：ブロック構成の設計

`references/html-blocks.md` の標準構成：

1. ファーストビュー強調（商品名・キャッチ・主要訴求3点）
2. 商品特徴（差別化ポイント・画像連携）
3. 比較表（自社バリエーション比較／競合比較／用途比較）
4. スペック表（サイズ・素材・容量・機能）
5. 使用シーン・使い方
6. FAQ（3〜7個）
7. 保証・配送・返品案内
8. クロージング（送料・あす楽・レビュー・関連商品）

### Step 3：比較表とFAQの選定

`references/comparison-faq.md` を参照：
- 比較表：自社バリエーション（標準／上位／下位）または用途別（家庭用／業務用）
- FAQ：購入不安を下部で解消、サイズ・素材・成分・配送・返品を網羅

### Step 4：HTMLコード生成

利用可能タグ：table、tr、td、th、br、font、b、strong、img、a、p、ul、li、h2、h3
禁止／非推奨：script、iframe、form、style属性の濫用、外部CSS／JS

table属性で横幅指定（PC向け）、imgはalt属性必須。

### Step 5：byte数チェック

生成HTMLをShift_JIS換算でカウント。10,240byte超過時は短縮版を提示。

### Step 6：画像とテキストの役割分離

重要情報（サイズ・成分・価格・保証）は必ずテキストでも記載。画像表示不可の環境（読み上げ・低帯域）でも情報が伝わる構成にする。

### Step 7：SP版との役割分担

PC版はテキスト量と比較表を厚く、SP版は縦スクロールに最適化（別スキル `rakuten-smartphone-description-html` で対応）。同じHTMLを両方に貼らない。

## 代表例

### 例：電気ケトル（家電・温度調整機能）

````html
<h2>1L大容量×6段階温度調整 電気ケトル</h2>
<p><b>赤ちゃんのミルク、コーヒー、お茶、白湯。すべて最適な温度で。</b></p>
<table border="1" cellpadding="8" width="100%">
<tr><th>項目</th><th>本商品</th><th>標準モデル</th></tr>
<tr><td>容量</td><td>1.0L</td><td>0.8L</td></tr>
<tr><td>温度調整</td><td>6段階（40〜100℃）</td><td>沸騰のみ</td></tr>
<tr><td>保温</td><td>1時間</td><td>なし</td></tr>
</table>

<h3>よくあるご質問</h3>
<p><b>Q. 空焚き防止機能はありますか？</b><br>
A. ございます。水量センサーが空状態を検知し自動停止します。</p>
````

完全な4パターン実例は `references/examples.md` を参照。

## 品質ゲート

- 生成HTMLが10,240byte以内（Shift_JIS換算）か
- 利用タグが楽天で許可されたタグのみか（script/iframe/form/style属性の濫用なし）
- 重要情報（価格・サイズ・成分・保証）が画像だけでなくテキストでも記載されているか
- img要素全てにalt属性があるか
- 比較表に客観項目（数値・仕様）が含まれ、主観評価のみで構成されていないか
- 「最安」「絶対」「業界一」等の景表法リスク表現がないか
- 化粧品・健食の場合、薬機法対象表現（「治る」「効く」「シミが消える」）がないか

## エッジケース

- **byte数オーバー時**：FAQと比較表を短縮版（references/comparison-faq.md の短縮型）に置換
- **画像未確定**：プレースホルダ（[画像1：商品全体]）で構造を先に生成、画像URL後挿入
- **化粧品・健食**：薬機法対象。「実感」「すこやか」程度に留め、効能訴求を回避
- **食品**：原材料・賞味期限・保存方法・アレルゲン表示を必ず含める
- **家具・大型商品**：搬入経路・組立有無・サイズ確認の注意書きを下部に必須

## 注意事項

- 楽天RMS仕様（許可HTMLタグ・byte上限）は随時改定。最終公開前にRMSヘルプを確認
- 文字コードはShift_JIS(CP932)、改行CR+LF。UTF-8で生成した場合は変換時に文字化けリスク
- 画像のテキスト占有率20%以内、白基調背景の規定（2024.6改定）に注意
- 価格・期間限定キャンペーンの文言を本文中に埋め込むと、終了後の差し替え漏れが頻発するため、別ブロック化推奨
- 景表法（「No.1」「最安」根拠なし）、薬機法（効能訴求）、特商法（保証・返品リンク不備）に注意
- 顧客個人情報・ログイン情報・他社商品の画像をSKILL.mdや出力例に保存しない
