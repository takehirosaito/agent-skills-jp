# 商品ページとフィードの整合チェック

GMCは送信されたフィードを取り込むと同時に、`link` で指定された商品ページをクロールし、フィード値と商品ページの表示が一致するかチェックする。**不一致は即不承認**になる。

## チェックされる主な項目

| フィード属性 | 商品ページで確認される項目 |
|---|---|
| price | 商品ページの最終販売価格（税込） |
| availability | 在庫表示（「在庫あり」「在庫切れ」等） |
| shipping | 送料表示 |
| title | （部分一致でOK、完全一致は不要） |
| image_link | （ページ内に同じか類似画像があると望ましい） |
| brand | （ページ内のブランド表記） |
| condition | （新品／中古の表示） |

## 1. 価格の整合

### よくある不一致

| フィード | 商品ページ | 原因 |
|---|---|---|
| 1980 JPY | 2,180円（税込） | フィード税抜・ページ税込 |
| 1980 JPY | 1,800円（セール中） | セール価格が反映されていない |
| 1980 JPY | 「ログインして価格表示」 | 会員価格表示で非ログイン時に見えない |
| 1980 JPY | 「ご注文時にお見積もり」 | 価格未確定商品 |

### 正しい設定

- **税込最終価格をフィードに入れる**（日本は税込が標準）
- セール時：`price` に通常価格、`sale_price` にセール価格＋期間
- 商品ページの価格表記を「2,180円（税込）」で統一

### 検査方法

1. フィードの `price` を抽出
2. 商品ページの価格表示部分を取得（DOM抽出、構造化データ）
3. 数値比較
4. 通貨単位の整合
5. 税込／税抜の整合

### 構造化データの活用

商品ページに **Schema.org Product 構造化データ** を入れると、Googleが価格を機械的に取得できる。不一致が減る。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org/",
  "@type": "Product",
  "name": "軽量Tシャツ",
  "offers": {
    "@type": "Offer",
    "price": "2180",
    "priceCurrency": "JPY",
    "availability": "https://schema.org/InStock"
  }
}
</script>
```

## 2. 在庫の整合

### よくある不一致

| フィード | 商品ページ |
|---|---|
| in_stock | 「在庫切れ」表示 |
| out_of_stock | 「在庫あり」表示 |
| in_stock | 「予約販売」表示 |

### 正しい設定

- 在庫変動を商品ページとフィードでリアルタイム連動
- 在庫管理：ネクストエンジン／クロスモール／PIM → ECサイト＋GMC同期
- フィード更新頻度：少なくとも1日1回、可能なら数時間毎

### 検査方法

1. フィードの `availability` を抽出
2. 商品ページの在庫表示部分を取得（クラス名／構造化データ）
3. マッピング：
   - in_stock ↔ 「在庫あり」「カートに追加可能」
   - out_of_stock ↔ 「在庫切れ」「販売停止」「Sold Out」
   - preorder ↔ 「予約販売」「予約受付中」
   - backorder ↔ 「お取り寄せ」「入荷待ち」

## 3. 送料の整合

### よくある不一致

| フィード | 商品ページ |
|---|---|
| shipping price 0 JPY | 「送料500円」表記 |
| shipping price 500 JPY | 「送料無料」表記 |
| shipping price 500 JPY（全国） | 「北海道・沖縄追加料金」 |

### 正しい設定

- フィードの shipping は商品ページの送料計算ロジックと一致させる
- 地域別送料は shipping 属性で複数行設定
- 「送料無料」キャンペーン期間中はフィードも 0 JPY に更新

### 設定例

全国一律送料：
```
shipping: country:JP,service:Standard,price:500 JPY
```

地域別送料：
```
shipping: country:JP,region:Hokkaido,service:Standard,price:1500 JPY
shipping: country:JP,region:Okinawa,service:Standard,price:1500 JPY
shipping: country:JP,service:Standard,price:500 JPY
```

GMCの「配送設定」を使う方法もある（個別商品でなくアカウント全体で設定）。

## 4. タイトルの整合

### 完全一致は不要だが…

- フィードのtitleと商品ページのタイトル（`<title>` タグや `<h1>`）が大きく異なるとペナルティ
- 商品の本質（ブランド・商品名・カテゴリ）が一致していれば良い

### 不一致の例

| フィード | 商品ページ |
|---|---|
| 軽量Tシャツ iPhone15 | （違う商品ページ） |
| Apple iPhone15 | 中華系コピー商品ページ |
| 軽量Tシャツ 送料無料 | プロモテキストがページにない |

## 5. 画像の整合

### チェック内容

- image_link が商品ページにある画像と類似しているか
- 画像URLが robots.txt で許可されているか
- 画像が実在し、HTTPSで取得可能か

### よくある問題

- 商品ページではモデル着用画像だが、フィードのimage_linkは別アングルや別商品
- 画像CDNがGooglebotをブロック
- 画像URLが古く、更新されたが商品ページは新画像

## 6. ブランド・商品状態

### ブランド
- フィードのbrandと商品ページのブランド表記が一致
- 「ノーブランド」「NB」等の表記揺れに注意

### 商品状態
- 新品 / 中古 / 整備済の表記が一致
- 「未使用品」と「新品」の区別

## 7. ランディングページの最適化

### Google向け推奨

1. **構造化データ（Schema.org Product）を実装**
2. **モバイルフレンドリー**（モバイル用LPは mobile_link 属性で指定可）
3. **Core Web Vitals**（速度・操作性・視覚的安定性）
4. **HTTPSアクセス可能**
5. **robots.txt で画像・商品ページの両方許可**
6. **404 / 5xx を出さない**

### 商品ページの必須要素

- 商品名
- 価格（税込）
- 送料情報
- 在庫状況
- 商品画像
- ブランド
- 商品状態（新品／中古）
- 商品コード（GTIN／MPN）
- 配送日数

## 8. 不一致が発生した場合の対応フロー

1. **GMCで不一致エラーを確認**
   - どの商品で、どの属性が不一致か
2. **商品ページを開いて確認**
   - 実際の表示値を確認
   - 構造化データを `テストツール` で検証
3. **不一致の原因を特定**
   - フィード側が古い／間違っている
   - 商品ページ側が古い／間違っている
4. **修正対象を決定**
   - 通常はフィードを正にする（リアルタイム性）
   - ただし商品ページが本来の値ならページを修正
5. **修正＋再アップロード**
6. **24-72時間後にエラー解除確認**

## 9. 定期検査の運用

- **日次**：フィード更新（在庫・価格の自動更新）
- **週次**：エラーレポートの確認、不一致の傾向把握
- **月次**：構造化データの正しさをテストツールで確認

## 10. 一致しなくても許容されるケース

- 細かい表記揺れ（「Tシャツ」と「ティーシャツ」）
- 商品名の前後の冠詞・キャッチコピー
- 商品ページの追加情報（フィードに含まれない仕様等）

ただし、価格・在庫・送料は厳密に一致させる必要がある。

## 検査スクリプト例（概念）

```python
def check_consistency(feed_item: dict, page_html: str) -> list[dict]:
    issues = []
    # 価格チェック
    page_price = extract_price_from_html(page_html)
    feed_price = parse_price(feed_item["price"])
    if abs(page_price - feed_price) > 1:  # 1円誤差許容
        issues.append({"attr": "price", "feed": feed_price, "page": page_price})
    # 在庫チェック
    page_avail = extract_availability_from_html(page_html)
    feed_avail = feed_item["availability"]
    if not avail_match(feed_avail, page_avail):
        issues.append({"attr": "availability", "feed": feed_avail, "page": page_avail})
    return issues
```

## まとめ

- フィードと商品ページの**価格・在庫・送料**は厳密に一致させる
- 商品ページに**構造化データ（Schema.org Product）**を入れる
- 商品ページの**表記を統一**（税込価格、在庫表示、送料表示）
- 不一致は**フィード側 OR 商品ページ側どちらが正か**を判断して修正
- 定期検査で**不一致の傾向**を把握し、運用フローを改善
