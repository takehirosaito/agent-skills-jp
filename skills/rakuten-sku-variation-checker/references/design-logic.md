# 設計判定ロジック（まとめる／分ける）

## 判定フロー

```
[商品が複数仕様]
  ↓
1. ターゲット顧客は同じか？
   No → 別商品
   Yes ↓
2. 商品の本質的な機能は同じか？
   No → 別商品
   Yes ↓
3. 価格差は±20%以内か？
   No → 別商品検討
   Yes ↓
4. 性別違い？
   Yes → 別商品（性別ジャンル分離のため）
   No ↓
5. 旧モデル・新モデル？
   Yes → 別商品（カタログ統合不可）
   No ↓
6. セット内容違い？（単品 vs セット）
   Yes → 別商品
   No ↓
[バリエーションでまとめる]
```

## まとめるべきケース

### 1. 完全同一商品の色違い・サイズ違い

例：
- 「ワンピース ブラック」「ワンピース ネイビー」「ワンピース ベージュ」
  → 1商品＋3色SKU
- 「Tシャツ S」「Tシャツ M」「Tシャツ L」
  → 1商品＋3サイズSKU

判定軸：
- 同じ商品名・素材・デザイン
- 同じターゲット
- 価格差±20%以内

### 2. 容量違いの同種商品

例：
- 「化粧水 100ml」「化粧水 200ml」「化粧水 300ml」
  → 1商品＋3容量SKU

判定軸：
- 同じ成分・処方
- 容量と価格が比例関係（300mlは100mlの2.5-3倍）

### 3. セット数違い

例：
- 「ハンドクリーム 1個」「ハンドクリーム 3個セット」「ハンドクリーム 6個セット」
  → 1商品＋3セット数SKU

判定軸：
- 同じ商品の数量違い
- まとめ買いほど単価が下がる

## 分けるべきケース

### 1. 性別違い

例：
- 「ジャケット メンズ」「ジャケット レディース」
  → 別商品（メンズジャンル・レディースジャンルで分かれる）

理由：
- 楽天の性別ジャンル検索（メンズファッション 551177、レディースファッション 100371）
- 1商品にまとめると、片方の性別検索で出ない

### 2. 旧モデル・新モデル

例：
- 「掃除機 ○○モデル 2022年版」「掃除機 ○○モデル 2024年版」
  → 別商品

理由：
- スペックが大幅に異なる
- 旧モデルは終売前提
- 顧客は「最新版」か「旧モデルセール」か明確に選びたい

### 3. 大幅な機能・素材違い

例：
- 「コットンTシャツ」「リネンTシャツ」
  → 別商品（素材で別商品）

判定軸：
- 素材・機能が大きく異なる
- 顧客の選好が異なる

### 4. 価格差が大きい

例：
- 「通常版 3,000円」「プレミアム版 8,000円」
  → 別商品

理由：
- 価格差が±50%以上だと「同じ商品」と感じにくい
- カート投入率も別

### 5. ターゲットが異なる

例：
- 「子供用」「大人用」
- 「業務用」「家庭用」
  → 別商品

理由：
- 検索キーワードが完全に違う
- 価格・スペックも違う

### 6. セット商品と単品

例：
- 「化粧水 単品」「化粧水＋乳液 2点セット」「3点セット」
  → 別商品

理由：
- 商品名・内容が違う
- 検索キーワードが違う（「セット」「単品」）
- 価格構造が違う

## グレーゾーンの判断

### 同種だがサイズが極端に違う

例：
- 「Sサイズ」「Mサイズ」「Lサイズ」 → まとめる
- 「Sサイズ」「3Lサイズ（特大）」 → 別商品検討

判断軸：
- ターゲット顧客が同じか
- 価格差
- 検索キーワードの違い（「3Lサイズ」「大きいサイズ」専門検索）

### 通常品と限定品

例：
- 「通常デザイン」「コラボデザイン」
  → 別商品検討

判断軸：
- コラボの認知度
- 別商品として独自SEOを取りたいか
- レビュー分散の影響

## 設計変更の影響

### バリエーションをまとめる場合
- 既存の別商品を1商品に統合
- レビュー数の合算が可能か確認
- URLが変わるためSEO影響あり

### バリエーションを分ける場合
- 既存SKUを別商品として登録
- レビューは元の親商品に残る
- 新商品としてSEO構築

### どちらが良いかの判断

| 状況 | 推奨 |
|---|---|
| 既存レビューを生かしたい | まとめる |
| 性別検索で両方拾いたい | 分ける |
| ロングテール検索を取りたい | 分ける |
| 商品ページ管理を一本化したい | まとめる |
| カテゴリ別ランキング両方狙いたい | 分ける |

## 競合店舗の事例分析

新規設計時は、楽天で類似商品を扱う上位店舗のバリエーション設計を観察：

- 何でまとめているか
- 何で分けているか
- SKU数の規模

ベンチマーク後に自社の戦略を決める。

## 大量SKUの場合（30以上）

SKU数が多すぎると：
- スマホで選びにくい
- 在庫管理が複雑
- 不人気SKUに広告費が割かれる

対応：
- 主力SKUと不人気SKUを分ける
- 「定番ライン」と「特殊ライン」で別商品化
- 「フリーサイズ」「ワンサイズ」での簡素化を検討

## バリエーション設計の改善タイミング

### 新商品登録時
- 設計をしっかり考える

### 既存商品の見直し
- 売上不振時
- 競合分析後
- SKU構成の大幅変更時（追加・削除）

### 季節商品
- 毎シーズン前に見直し

## チェックリスト

バリエーション設計判定：

- [ ] ターゲット顧客が同じか
- [ ] 機能・素材が同じか
- [ ] 価格差が±20%以内か
- [ ] 性別違いではないか
- [ ] 旧/新モデルではないか
- [ ] 単品/セットではないか
- [ ] 競合店舗のベンチマークを確認した
- [ ] レビュー分散の影響を考慮した
- [ ] SEOへの影響を考慮した

すべてYesなら「まとめる」、Noが1つでもあれば「分ける」を再検討。
